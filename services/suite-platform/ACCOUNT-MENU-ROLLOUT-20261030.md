## 카카오·네이버 프로필 서버 변경 — 별도 운영 배포 필요

기존 콜백은 공급자 ID만 사용해 Firebase 사용자를 만들고 사진과 이름을 버리고 있었다. `provider-profile.mjs`가 허용된 응답의 표시 이름/이미지 URL만 Firebase Auth 사용자에 반영한다. UID 연결 방식은 유지하고 이메일로 병합하지 않는다. 원본 응답·토큰은 저장하지 않는다. 일반 로그인에서 사진이 없어지면 오래된 사진을 비우고, 다른 SNS 연결에서는 기존 프로필을 덮어쓰지 않는다. 관련 단위 테스트 6개 통과.

GitHub Pages 배포는 Firebase Functions를 배포하지 않는다. 이 변경의 서버 운영 배포를 완료했다고 보고하면 안 된다. 기존에 인증된 배포 환경과 기존 `SUITE_ENABLE_SOCIAL=true`, 공급자 client ID, Secret Manager 설정을 유지해야 한다. 빈 환경변수 파일을 만들어 기존 설정을 덮어쓰거나 다른 Firebase 프로젝트를 선택하지 않는다.

기존 배포 환경에서 소스를 갱신한 뒤 `services/suite-platform`에서 의존성/검사를 수행하고 `suite-platform` 코드베이스의 `suiteSocialAuth`를 한정 재배포한다. 프로젝트는 `softm-hannun-api`다. 배포 후 `/suiteSocialAuth/health` 응답의 `profileVersion`이 `20261030-1`인지 확인하고, 실제 카카오 로그인 후 사진 표시를 확인한다. 네이버 일반 공개 로그인은 기존 검수 상태에 따르며 승인 완료로 바꾸지 않았다.

프로필 사진 변경 반영 검증은 새 SNS 로그인으로 수행한다. 이전 세션의 사용자 캐시나 사진 제공 미동의는 이름 첫 글자로 표시될 수 있다. 실제 OAuth 성공과 공급자 동의 여부는 합성 UI 테스트로 대신 확인하지 않는다.
