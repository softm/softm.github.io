# Android 배포 공통 키스토어 규칙

사용자 지정일: 2026-10-30

## 적용 범위

모든 Android 앱의 배포 서명에는 사용자가 보유한 기존 공통 `softm.keystore.jks`를 사용한다. `/Users/softm/makeme` 아래의 Android 앱도 예외 없이 포함한다. 사용자의 명시적인 별도 지시가 있으면 그 지시를 우선한다.

이 문서는 배포 원칙이며, 모든 기존 앱이 이미 이 키로 배포됐다는 뜻은 아니다. 문서 반영만으로 기존 앱의 설정 변경·재서명·업로드·키 재설정·검토 취소를 수행하지 않는다.

## 기준 파일

- 기준 경로: `/Users/softm/workspace/softm.navi.poweron.new/softm.keystore.jks`
- 동일 파일로 확인한 복사본:
  - `/Users/softm/workspace/softm.navi.shortcut/softm.keystore.jks`
  - `/Users/softm/workspace/softm.bluetooth.music/softm.keystore.jks`
- 확인 당시 파일 SHA-256: `7d7a15b6659180f427528c3684d892902e157cbda88a4c0cd7588507c94ecf62`
- 확인 당시 서명 인증서 SHA-256: `8D:50:96:09:80:83:90:20:81:0E:91:D2:26:A8:1E:9D:B9:0B:26:36:0B:14:2D:00:0F:97:B2:DA:78:69:21:0E`

파일 해시는 키스토어 파일 자체를 식별하고, 인증서 지문은 서명 인증서를 식별한다. 두 값은 서로 다른 값이며 비교 대상을 혼동하지 않는다. 비밀번호와 키 파일 자체는 이 문서에 포함하지 않는다.

## 서명 및 배포 절차

1. 실제 사용할 키스토어 경로와 인증서를 확인한다. 파일명이 같다는 이유만으로 동일 키라고 판단하지 않는다.
2. 대상 앱의 Google Play 등록 업로드 인증서와 공통 키 인증서가 일치하는지 확인한다. Play 앱 서명 인증서와 업로드 인증서를 구분한다.
3. 불일치하거나 등록 인증서를 확인할 수 없으면 업로드를 진행하지 않고, 확인한 사실과 미확인 사항을 사용자에게 알린다. 임의로 다른 키를 사용하거나 새 키를 생성하거나 업로드 키 재설정을 요청하지 않는다.
4. 승인된 키로 AAB를 서명한 후 산출물의 서명 인증서, 패키지명, 버전 정보를 확인한다. 서명 검증 성공만으로 Play 업로드 인증서와 일치한다고 판단하지 않는다.
5. 빌드 완료, 업로드 완료, 검토 제출, 실제 배포를 구분해서 보고한다. 진행 중인 검토를 임의로 취소하지 않는다.

## 기존 프로젝트 조사 시 주의사항

- 프로젝트에 별도 `.jks` 파일이 있거나 Gradle·CI 설정에 연결되어 있어도 사용자의 사용 승인으로 해석하지 않는다. `evchargingstation-upload.jks`도 공통 키의 대체 파일로 사용하지 않는다.
- 서명 설정은 설정의 증거, 로컬 AAB 인증서는 해당 파일의 증거다. 실제 제출 파일이나 Play 등록 인증서 확인 없이 실제 배포 키로 단정하지 않는다.
- 과거 키 재설정 요청이 있으면 요청일, 적용 예정 시각, 현재 등록 인증서를 구분한다. 요청 이력만으로 기존 키의 사용 가능 여부를 단정하지 않는다.
- 과거 정책 거부 기록과 이후 재제출·현재 검토 상태를 구분한다.
- 기존에 다른 키를 쓴 앱을 발견해도 일괄 변경하지 않는다. 사용자에게 앱별 차이를 보고하고 명시적인 지시에 따라 처리한다.

## 비밀정보 보관

키스토어 파일, 개인 키, 비밀번호, 서비스 계정 인증정보를 저장소에 커밋하거나 로그·채팅·공개 문서에 노출하지 않는다. 기존에 안전하게 보관된 설정을 사용하며 비밀번호를 채팅에 붙여 넣도록 요구하지 않는다.
