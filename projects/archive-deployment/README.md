## 먼저 읽을 실행 기준

**`정리 md, html to zip` 실행은 [MD · HTML · ZIP 통합 실행 프롬프트](MD-HTML-ZIP-PROMPT.md)를 기준으로 한다.** 현재 채팅 전체, 모든 원본 미디어, 사건일 기반 파일명, 실제 MD/HTML/ZIP 생성, 기존 공개·비공개 배포 연계, 홈·중앙 인덱스·인증·미디어 검증과 완료 보고까지 포함한다.

사용자가 명시한 범위 제한이 우선한다. 프롬프트나 기준 문서 작성 요청을 개인 기록 공개나 전체 프로젝트 재배포 요청으로 확대하지 않는다.

## 충돌 시 우선순위

현재 요청의 명시적 범위 → 최신 사용자 확정 변경사항 → 통합 실행 프롬프트 → 충돌하지 않는 기존 세부 운영 기준 순으로 적용한다. 보존 문서의 오래된 문구로 최신 기준을 되돌리지 않는다.

정상 HTML이 있으면 우선 보존한다. HTML이 없으면 MD/TXT/미디어/문서에서 HTML을 만든다. Markdown 덤프형 HTML은 원본을 보존하면서 정상 렌더링 HTML로 정규화한다. 따라서 과거의 포괄적 MD 변환 금지·HTML 없으면 중단 문구는 그대로 적용하지 않는다.

## 중앙 기준 갱신 의무

어느 프로젝트에서든 새 규칙·사용자 요구·오류 수정 기준이 확정되면 해당 채팅에만 남기지 않고 이 중앙 소스, 변경 이력 및 필요한 공통 구현과 대상 프로젝트에 함께 반영한다. 전역 기억 저장 요청도 함께 처리한다.

소스 수정, 서비스 구현, 운영 검증, 전역 기억 저장, ChatGPT 프로젝트 첨부는 서로 다른 작업이다. 수행하지 않은 단계까지 완료로 보고하지 않는다. 이 디렉터리에는 공통 정책만 기록하고 개인 민감 원문이나 인증정보를 넣지 않는다.

## 2026-10-07 보완: 미디어·문서 기본 뷰어/플레이어

아카이브 상세페이지는 원본 파일 링크만 나열하는 방식으로 끝내지 않는다. 브라우저에서 바로 확인 가능한 자료는 각 형식에 맞는 뷰어 또는 플레이어를 기본 제공한다.

### 형식별 기본 표시 기준

| 자료 형식 | 기본 UI |
|---|---|
| Markdown / TXT / 로그 / 녹취 텍스트 | 읽기용 텍스트 뷰어. 줄바꿈·공백 유지, 긴 문서는 스크롤 영역 또는 접기/펼치기 지원 |
| JPG / JPEG / PNG / WEBP / GIF / AVIF / SVG | 이미지 뷰어. 반응형 표시, 원본 열기, 클릭 확대/라이트박스 지원 |
| MP4 / WEBM / MOV / M4V | HTML5 비디오 플레이어. controls, preload=metadata, 원본 열기 제공 |
| MP3 / M4A / WAV / OGG / FLAC / AAC | HTML5 오디오 플레이어. controls, preload=metadata, 원본 열기 제공 |
| PDF | 브라우저 PDF 뷰어(`iframe`/embed)와 별도 원본 열기 링크 제공 |
| DOC/DOCX/XLS/XLSX/PPT/PPTX/HWP/HWPX 등 | 브라우저 직접 표시가 안정적이지 않으면 파일 카드 + 원본 다운로드/열기. 가능한 경우 별도 미리보기 제공 |
| ZIP / 7Z 등 압축 파일 | 파일 카드, 크기·파일명 표시, 원본 다운로드 링크 |
| 기타 바이너리 | 파일 카드와 원본 다운로드 링크 |

### 이미지 뷰어 기준

이미지는 단순 `<img>` 나열만 하지 않고 다음을 우선 적용한다.

- 썸네일/반응형 갤러리
- 클릭 시 원본 크기 확대
- 좌우 이동 또는 이전/다음 탐색
- 파일명/캡션 표시
- 원본 열기
- 모바일 화면 대응

### 영상·음성 플레이어 기준

- 브라우저 기본 controls 제공
- preload는 원칙적으로 `metadata`
- 영상은 모바일 너비에 맞춰 반응형 처리
- 음성은 전체 너비 플레이어 제공
- 재생 불가 브라우저를 위해 원본 파일 링크를 함께 제공
- 다수 파일은 목록/플레이리스트 형태로 정리할 수 있다

### 텍스트 뷰어 기준

- TXT/녹취/로그는 HTML에서 바로 읽을 수 있어야 한다.
- `<pre>` 또는 읽기 전용 뷰어를 사용해 줄바꿈과 공백을 보존한다.
- 파일이 긴 경우 페이지 전체를 과도하게 늘리지 않도록 접기/펼치기 또는 제한 높이 + 내부 스크롤을 적용할 수 있다.
- 원본 TXT 다운로드/열기 링크를 함께 제공한다.

### PDF 뷰어 기준

PDF는 가능하면 상세페이지 안에서 바로 볼 수 있게 한다.

```html
<iframe src="document.pdf" title="PDF 미리보기"></iframe>
```

또는 브라우저 지원에 맞는 `embed`를 사용한다. 별도 원본 열기 링크는 반드시 유지한다.

### 원본 보존과 뷰어 관계

뷰어/플레이어는 원본을 대체하지 않는다.

- 원본 파일은 저장소에 그대로 보존한다.
- 뷰어는 원본 상대경로를 사용한다.
- manifest에는 원본 파일의 크기·SHA-256을 기록한다.
- 자동 생성 썸네일/프리뷰가 있다면 원본과 구분한다.
- 원본 직접 열기 또는 다운로드 경로를 유지한다.

### 완료 검증 추가

아카이브 배포 완료 전에 다음을 실제 확인한다.

- 이미지가 실제 표시되는지
- 이미지 확대/원본 열기가 동작하는지
- 영상이 실제 재생되는지
- 음성이 실제 재생되는지
- TXT/녹취가 페이지 내에서 읽히는지
- PDF 뷰어가 로드되는지
- 원본 파일 링크가 404/403/500 없이 동작하는지
- 비공개 자료는 인증 전 직접 접근되지 않는지

즉, **아카이브는 파일 저장소가 아니라 브라우저에서 바로 열람 가능한 기록 뷰어까지 제공하는 것을 기본 기준으로 한다.**

## 2026-10-07 보완: 신규 비공개 프로젝트 연결과 단일 처리 경로

기존 공용 GitHub 토큰을 새 비공개 프로젝트에 연결할 때는 세 항목을 따로 확인한다: Vercel GitHub App의 저장소 허용, Shared 환경변수의 프로젝트·운영 환경 연결, 기존 fine-grained 토큰의 대상 저장소·Contents 읽기 권한. 빈 프로젝트별 환경변수 목록만으로 공용변수 부재를 단정하거나 새 토큰 생성을 요구하지 않는다. 진단은 토큰 값 없이 원본 저장소와 진입 파일의 응답 상태로 확인한다.

동일 저장소의 구형 HTML-only 빌더와 최신 수집함 빌더를 동시에 실행하지 않는다. 기존 canonical 식별자를 재사용하고, 과거 주소를 보존해야 할 때는 aliasOf로 표시하여 목록에서 중복을 제외한다. 정상 HTML은 바이트 그대로 유지하며 PDF/DOCX-only 자료도 제외하지 않고 PDF 뷰어와 문서 원본 링크를 제공한다.

운영 홈페이지 정상 응답과 첨부 미디어·브라우저 검증은 별도 단계다. 비공개 원문이나 인증정보를 중앙 Public 저장소로 복사하지 않고, 이미 공개된 목록 메타데이터에 인증된 운영 링크만 연결한다. 최종 운영·미디어·중앙 목록 검증 전에는 zip/ 입력을 삭제하지 않는다.
