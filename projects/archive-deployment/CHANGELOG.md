# 아카이브 배포 — 기준 변경 이력

## 2026-10-05 · 모든 프로젝트의 기준 변경을 중앙에 반영

사용자 확정 기준:

> 변경되거나 보완되는 아카이브 기준정보는 “아카이브 배포” 프로젝트에도 반영한다. 개별 프로젝트나 채팅에서만 수정하고 끝내지 않는다.

적용 범위는 공개·비공개 배포 및 ZIP/폴더, HTML, 미디어, 메타데이터, 인증, 목록, 검증, 정리, 완료 보고의 모든 기준이다.

기준 변경 작업의 완료 조건은 **중앙 기준 문서 갱신 + 관련 구현 반영 + 실제 검증 + 반영 위치 보고**다. 메모리 저장 성공과 중앙 기준 문서 반영 성공은 별개로 확인한다. 저장 기능이 실패하면 전역 기억에 저장했다고 말하지 않는다.

중앙 기준 소스: [README.md](README.md), [통합 프롬프트](archive_deployment_prompt.md), [ZIP·폴더 Workflow 처리기준](20261005_아카이브배포_ZIP폴더_Workflow_처리기준.md).

## 2026-10-05 · ZIP 내부 HTML을 기준으로 진입점 구성

- ZIP 디렉터리의 `index.html` 구성 기준은 **MD 파일이 아니라 포함된 HTML 파일**이다.
- 기존 HTML의 내용·레이아웃·상대경로·미디어 연결을 보존한다.
- 기존 HTML을 무시하고 MD로 본문을 재생성하거나 TSX 등으로 재작성하지 않는다.
- HTML이 없는 입력은 누락 상태를 명시하고 별도 처리하며, 정상 HTML 배포로 간주하지 않는다.
- 이 규칙은 기존 문서의 포괄적인 “HTML/Markdown을 구성한다”는 표현보다 우선한다.

## 2026-10-05 · ZIP 배포 후 세 목록의 단일 원본

### 문제

`softm/hwagok-farm`의 ZIP 처리 결과는 프로젝트 홈의 `script#archive-data`에 반영됐지만 중앙 `projects/projects.json`은 별도 정적 목록이어서 중앙 프로젝트 홈의 공개 목록이 뒤처졌다.

### 확정 기준

| 구분 | 원칙 |
|---|---|
| 원본 | 프로젝트 저장소에서 생성하여 실제 배포한 canonical 공개 목록 |
| 공개 프로젝트 홈 | 해당 원본을 렌더링 |
| 중앙 `/projects/<project>/` | 같은 원본을 읽어 기록 수·date/title/slug·상세 링크·GitHub 디렉터리 링크를 표시 |
| 최상위 `/projects/` | 같은 원본으로 공개 기록 수와 최근 기록을 계산 |
| 중앙 등록부 | 프로젝트 정보·원본 목록 연결정보 관리. 별도 수동 기록 목록을 최신 목록처럼 사용하지 않음 |
| 자동 복제가 필요한 경우 | 동일 원본에서 자동 생성하고 배포 후 일치 검증. 장기적으로 독립 편집되는 이중 목록 금지 |
| 실패 | 오류를 표시하고 원본 홈 링크 제공. 낡은 스냅샷을 최신 동기화 성공 결과로 표시하지 않음 |
| 공개 범위 | 비공개 원문·미디어는 조회하거나 공개 복제하지 않음 |

### 검증과 입력 삭제

소스 수정, commit 또는 CI 성공만으로 완료하지 않는다. 프로젝트 홈·중앙 프로젝트 홈·최상위 목록의 실제 브라우저 렌더링, 기록 수와 메타데이터·링크 일치를 확인한다. 상세 HTML·미디어는 원래 프로젝트 저장소에 유지한다. 배포·최종 검증이 끝나지 않은 `zip/` 입력은 삭제하지 않는다.

### 구현 원칙

공개 프로젝트의 배포 HTML에 `script#archive-data[type="application/json"]`가 있으면 이를 읽거나, 같은 빌드에서 생성한 공식 manifest를 읽을 수 있다. HTML 소스에서 메타데이터만 읽고 그 HTML의 스크립트를 실행하지 않는다. HTTPS·동일 공개 프로젝트 경로·고유 slug·예상 상세 URL·GitHub 원본 디렉터리를 검증한다. 캐시 때문에 오래된 목록을 사용하지 않도록 조회·배포 버전 관리를 포함한다.


## 2026-10-06 · 개별 배포 성공 후 중앙 프로젝트 페이지 누락 방지

### 발생한 문제

`hwagok-farm-private` ZIP 아카이브 처리에서 개별 Private GitHub 반영과 Vercel `READY`까지 확인한 뒤 작업을 완료로 판단하여, 중앙 `projects/projects.json`, `/projects/hwagok-farm/`, 최상위 `/projects/` 반영이 작업 종료 시점에 누락되었다.

### 확정 보완 기준

- Vercel `READY`, Pages 성공, Git commit 성공은 **중간 성공 상태**다.
- 아카이브 배포는 개별 기록 → 프로젝트 홈 → 중앙 프로젝트 홈 → 전체 프로젝트 인덱스 → 실제 링크/인증/미디어 검증까지 한 작업으로 수행한다.
- 공개·비공개 기록 모두 중앙 프로젝트 메타데이터를 갱신한다.
- 새 기록 추가 시 `projects/projects.json`의 공개/비공개 기록 수, 최신 기록, URL, 저장소 정보 등 관련 필드도 함께 갱신한다.
- `/projects/<project>/`와 `/projects/`의 실제 운영 화면 반영 확인 전에는 완료로 보고하지 않는다.
- 이 체크가 누락되면 설명만 하지 않고 즉시 중앙 반영까지 복구한다.

핵심 문구: **Vercel READY ≠ 아카이브 배포 완료.**

## 2026-10-07 · 비공개 아카이브 Vercel 역할 및 Shared Token 판정 강화

화곡리 개간허가 비공개 아카이브 작업에서 Private GitHub의 `zip/` 원본을 Vercel 정적 배포물로 직접 제공한 오류를 계기로 다음 기준을 강제 규칙으로 확정했다.

- 비공개 원본은 Private GitHub만 Source of Truth로 유지한다.
- Vercel은 인증 + server-side GitHub live-read gateway 역할만 한다.
- `zip/`, `archive/`, HTML/PDF/이미지/영상/음성 원본을 Vercel static output에 복제하지 않는다.
- GitHub 저장소가 Vercel에 Git 연결되어 있어도 build 대상은 gateway/API 코드로 제한한다.
- Shared `GITHUB_TOKEN`은 프로젝트 전용 env 조회에서 보이지 않을 수 있다. 빈 조회 결과만으로 token 부재를 단정하지 않는다.
- 사용자가 Shared token 연결을 이미 확인했다면 token 재생성·재입력을 요구하지 않는다.
- 비공개 작업 전 `baksok-private`, `ungdo-private` 등 기존 정상 구현과 비교하는 preflight를 필수화한다.
- `READY`는 완료가 아니다. GitHub 최신 원본 live-read, 인증, 상대 미디어 경로, no-store, 중앙 링크를 실제 검증해야 한다.
- 오배포 발견 시 직접 원본 노출 차단 → gateway 전환 → 인증/운영 검증 → 중앙 인덱스 교정 → 중앙 기준 갱신 순으로 즉시 복구한다.
