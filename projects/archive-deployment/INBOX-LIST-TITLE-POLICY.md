# ZIP·폴더 아카이브 목록 제목 기준

확정일: 2026-10-08 · 기준 ID: inbox-name-list-title-v1

## 사용자 확정 규칙

**zip/ 수집함을 아카이브 배포할 때 목록의 제목은 입력 작업 폴더명 또는 ZIP 파일명 그대로 사용한다.** HTML H1·브라우저 title·MD 제목·자동 요약·생성 slug로 목록 제목을 대체하지 않는다.

| 입력 | 목록 제목 |
|---|---|
| `zip/<작업폴더>/` | `<작업폴더>`의 이름 그대로 |
| `zip/<파일명>.zip` | `<파일명>.zip`의 이름 그대로. 별도 지시 없이는 확장자도 보존 |
| ZIP 안의 폴더·HTML·MD | 목록 제목의 기준으로 사용하지 않음 |
| 사용자가 목록 제목을 별도로 지정 | 그 명시적 제목을 우선하고 원래 입력 이름은 메타데이터에 보존 |

상위 경로인 `zip/`은 제목에 포함하지 않는다. 이름 안의 날짜·한글·공백·밑줄·괄호·문장부호를 임의로 삭제하거나 다듬지 않는다. 날짜를 제목 앞에 다시 붙이거나 짧은 제목으로 요약하지 않는다. NFC/NFD 한글 정규화는 파일 경로 매칭과 표시 안정성에만 사용할 수 있으며 원래 입력 이름은 따로 보존한다.

## 목록과 본문 제목의 분리

- `inputName`: 확인된 입력 폴더명 또는 ZIP 파일명.
- `inputKind`: `folder` 또는 `zip`.
- `listTitle`: `inputName` 그대로. 사용자 명시적 목록 제목이 있는 경우에만 해당 제목.
- `titleSource`: `inbox-name` 또는 `user-list-title`.
- `title`·`label`: 기존 목록 구현의 호환 필드. 해당 입력 기록에서는 `listTitle`과 동일하게 유지.
- `sourceTitle`·`sourceDocumentTitle`: 기존 본문 H1·브라우저 제목. `listTitle`과 달라도 정상.
- 기존 `id`, `slug`, 사건일 `date`, URL, 원본 파일, 미디어 경로, 공개 범위와 인증은 유지.

**목록 제목을 맞추기 위해 정상 원본 HTML·MD의 제목이나 본문을 덮어쓰지 않는다.** 이 규칙은 기존의 모든 제목을 강제로 동일하게 만든다는 표현에 대한 ZIP·폴더 배포의 명시적 예외다.

## 세 목록의 동기화

프로젝트 자체 기록 목록 → 중앙 `/projects/<project>/` 기록 목록 → 최상위 `/projects/`에서 표시하는 관련 기록 제목/최근 기록 정보까지 같은 `listTitle`을 사용한다. 최상위 프로젝트 이름 자체를 파일명으로 바꾸지는 않는다. 새로운 기록이 과거 사건일이면 최신 기록으로 잘못 승격하지 않는다.

공개·비공개 배포 모두 같은 제목 규칙을 적용한다. 비공개 제목에 민감정보가 포함돼 공개 목록에 표시할 수 없는 경우에는 인증된 목록에 정확한 제목을 사용하고, 공개 화면에는 기존 최소 공개 메타데이터 정책을 적용한다. 제목 규칙은 비공개 자료 공개의 허가가 아니다.

## 재실행·기존 기록

입력 cleanup 후에는 manifest에 저장한 `inputName`, `input`의 마지막 경로 요소 또는 검증된 원래 `source`를 사용한다. 경로를 임의로 만들어 내지 않는다. 같은 기록의 제목만 변경하는 경우 기존 canonical URL과 식별자를 재사용하고 중복 기록을 만들지 않는다. 다른 프로젝트·다른 기록의 제목은 별도 요청 없이 일괄 변경하지 않는다.

## 완료 확인

1. 입력 폴더/ZIP 이름과 `listTitle`이 일치한다.
2. 프로젝트 자체 목록과 중앙 프로젝트 목록이 해당 제목을 실제 렌더링한다.
3. 제목 클릭은 기존 운영 상세페이지로 연결된다.
4. 원본 HTML·MD·미디어의 바이트와 경로는 그대로다.
5. 공개/비공개 기록 수와 다른 프로젝트 정보가 변하지 않는다.
6. 정책 문서 저장, 개별 코드 적용, 운영 화면 검증, 전역 메모리 저장은 서로 구분해서 보고한다.
