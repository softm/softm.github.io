# 프로젝트별 비공개 채팅 연결 조사

점검일: 2026-09-30 (한국 시간)

## 결론과 원칙

공개 목차에서 비공개 원문을 인증된 Vercel 서버로 연결하는 것 자체는 오류가 아니다. `PROJECT-HOME-POLICY.md`의 **프로젝트 공개 홈 → 공개·비공개 채팅 목록 → 선택한 원문** 원칙을 유지한다. 이번에 확인한 문제는 운영에 없는 URL을 정상적인 원문 열기 버튼으로 표시한 것과, 다른 프로젝트 저장소가 Vercel 배포에 연결된 것이다.

원문·사진·영상·음성은 이번 조사로 복사·삭제·축약하지 않았다. 이 보고서에는 공개 목차에 이미 있는 제목/주소와 연결 점검 상태만 기록한다. 개인 의료정보와 인증정보를 공개하지 않는다.

## 조사 범위와 한계

- 중앙 목록의 13개 프로젝트와 공통 목록 생성 코드를 검토했다.
- `projects/project-home.js`의 `ROUTES` 및 `projects/home-generator-core.py`의 `CHAT_PATHS`에는 7개 프로젝트, 38개의 비공개 경로가 있으며, 여기에 `projects.json`의 개별 링크를 병합한다. **38은 URL 정상 응답 확인 개수가 아니라 코드에 지정된 경로 개수다.**
- 위 7개 Vercel 프로젝트의 최신 배포를 조회해 배포 상태와 원본 저장소 연결을 대조했다.
- 아버지 병원 치료의 7개 `/archive/...` 주소는 Vercel 연결 도구로 각각 요청해 **모두 HTTP 404**를 확인했다. 이 요청 결과만으로 비로그인 사용자의 접근 제어 상태를 판정하지 않는다.
- 그 밖의 모든 채팅 URL에 대한 응답·로그인 후 본문·원본 미디어 재생 전수 검증은 아직 완료하지 않았다.
- 자동 전수 링크 검사 실행은 GitHub Actions가 실행 단계 진입 전에 `startup_failure`로 끝났다. 작업 로그가 없어 원인은 확정하지 않았다. 미실행 검사를 성공 또는 누락 0건으로 보고하지 않는다.

## 코드 수정 내용 — 서비스 복구와 구분

1. 공통 화면 보정 코드는 아버지 병원 치료의 위 7개 링크를 존재가 확인된 **각 기록의 비공개 GitHub HTML 원본**으로 연결하고, `GitHub HTML 원본 확인`이라고 표시한다. 이것은 웹 서비스 복구가 아니라 장애 중 원본을 확인하는 경로다. 제목·작성일·카드/목록/표/갤러리·정렬·기존 메타데이터는 유지한다.
2. 원래 Vercel 주소는 삭제하지 않고 오류 안내 안에 `기존 웹 주소 다시 확인 (복구 미확인)`으로 보존한다. 웹 재배포와 인증 후 원문 동작을 검증한 다음 이 한시적 보정을 제거해야 한다.
3. 화곡리 개간허가의 위 5개 링크는 정상 사이트 열기로 표시하지 않고 저장소 연결 오류 안내로 이동한다. 실제 원본 저장소 링크는 별도로 제공한다. 기존 주소도 오류 안내 안에 유지한다.
4. 다른 공개·비공개 링크는 임의로 바꾸지 않는다. 비공개 버튼에는 인증 서버로 이동한다는 설명을 추가한다. 공개 화면은 비공개 본문을 요청하지 않고 비밀번호를 입력받거나 클라이언트에서 인증을 흉내 내지 않는다.
5. 아버지 병원 치료 서버 소스는 로그인 전 요청 경로를 전달하고, 인증 성공 후 검증된 내부 경로로 돌아가도록 수정했다. 외부 URL·프로토콜 상대 URL·역슬래시·로그인 재귀 경로를 거부한다. **소스 커밋은 완료됐지만 운영 반영은 미완료다.**

## 실제 실시한 테스트

- 서버 내부 복귀 경로 검증: 16개 단위 테스트 통과.
- 공개 링크 보정 분류: 7개 원본 매핑, 5개 저장소 불일치 경로, 10개 미변경/부적합 URL 테스트 통과.
- 로컬 Chromium: 7개 오류 링크 보정, 공개 링크 유지, 원래 URL 메타데이터 유지, 표 보기 전환 후 재적용, 다른 프로젝트 서버로 무심코 이동하는 경로 차단을 확인했다.
- 로컬 UI 테스트 중 외부 네트워크 요청 0건, JavaScript 오류 0건.
- 위 테스트는 **로컬 테스트**이며 GitHub Pages 실서비스 최신 반영이나 Vercel 인증 후 열람을 대신하지 않는다.
