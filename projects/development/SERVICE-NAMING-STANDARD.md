# 서비스 명명 공통 기준 — 한눈과 해요

확정일: 2026-10-22 (대한민국 표준시)  
적용 범위: 새 서비스의 이름·제품 소개·저장소명·기획 문서를 정할 때 사용하는 공통 기준

## 1. 두 계열의 의미

| 계열 | 영문 접미사 | 제품의 중심 | 사용자의 질문 | 서비스의 역할 |
|---|---|---|---|---|
| 한눈 | hannun | 정보 탐색·파악·이해·비교 | 무엇이 있고 어떻게 다른가요? | 흩어진 정보를 모아 쉽게 찾고 판단하도록 도움 |
| 해요 | haeyo | 선택·준비·실행·진행·완료 | 어떻게 시작하고 지금 무엇을 해야 하나요? | 사용자가 일을 진행하고 끝낼 수 있도록 확인·소통·의사결정·기록을 보조 |

**한눈은 정보를 이해하고 비교하는 느낌, 해요는 함께 일을 진행해 나가는 느낌을 표현합니다.**

검색 기능의 유무나 체크리스트의 유무 하나로 계열을 정하지 않습니다. 서비스가 사용자의 어떤 목표를 중심으로 돕는지에 따라 이름을 선택합니다. 정보 탐색과 실행 보조가 함께 있다면 제품의 주된 목적을 기준으로 합니다.

## 2. 이름과 저장소 표기

- 한글 서비스명은 자연스럽게 붙여 씁니다. 예: 사업자한눈, 설계해요.
- 영문 저장소명은 주제명과 접미사를 붙여 씁니다.
- 예: bizhannun, seolgyehaeyo.
- 주제명과 hannun·haeyo 사이에는 대시를 넣지 않습니다.
- 공개·비공개 저장소 구분처럼 별도로 정한 운영 접미사는 해당 기준을 함께 적용합니다.
- 기존 서비스명을 일괄 변경하는 지시가 아닙니다. 이름을 바꿀 대상이 정해졌을 때 해당 저장소·문서·링크에 반영합니다.

## 3. 설계해요 적용 결정

| 항목 | 기준 |
|---|---|
| 서비스명 | 설계해요 |
| 저장소 | [softm/seolgyehaeyo](https://github.com/softm/seolgyehaeyo) |
| 계열 | 해요 · haeyo |
| 주 사용자 | 설계 업무를 맡기는 의뢰자 |
| 서비스 정의 | 설계사무소를 잘 고르고, 의뢰한 업무가 잘 진행되고 마무리되도록 의뢰자의 확인·소통·의사결정을 보조 |
| 짧은 소개 | 좋은 설계사무소를 고르고, 맡긴 일이 끝까지 잘 진행되도록. |
| 돕는 과정 | 요구사항 정리 → 후보 비교 → 견적·계약 확인 → 수행·변경 관리 → 준공·인수·정산 |

설계해요의 주체는 설계 업무를 맡기는 의뢰자입니다. 전문 업무를 수행하는 담당자의 역할을 구분하고, 의뢰자에게 지금 할 일과 확인할 자료를 쉽게 안내하는 방향으로 기획합니다.

## 4. 이후 기획·개발에 적용

새 서비스를 기획하거나 이름을 제안할 때 이 기준을 확인합니다. 선택한 계열과 서비스의 주된 목적을 README에 짧게 명시하고, 기능·화면·소개 문구에도 같은 관점을 반영합니다.

공통 기준에 대한 후속 사용자 지시가 있으면 이 문서를 갱신하고, 영향을 받는 프로젝트 문서에도 연결합니다.
