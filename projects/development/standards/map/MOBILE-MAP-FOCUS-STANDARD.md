# 모바일 지도 집중모드 전역 표준

최종 갱신: 2026-10-23

이 문서는 지도 중심 웹앱에서 모바일 사용자가 마커를 선택하거나 지도를 넓혀 보고 싶을 때 적용하는 공통 UX/구현 기준이다. 기준 UX는 돌봄한눈의 모바일 지도 상세 흐름이다.

## 1. 호출 키워드

다음 표현은 모두 같은 작업 지시로 해석한다.

- `돌봄한눈식 모바일 지도 집중모드 적용`
- `지도 집중모드 적용`
- `돌봄한눈 지도모드 적용`
- `모바일 지도 전체모드 적용`
- `돌봄한눈처럼 마커 상세 + 전체지도`

사용자가 서비스명과 함께 위 표현을 말하면, 별도 기획 설명만 하지 말고 해당 서비스의 실제 지도 UI와 상태 관리 구조를 확인한 뒤 가능한 범위에서 소스 수정, 테스트, 푸시, 배포 검증까지 진행한다.

예:
- `경매한눈 지도 집중모드 적용`
- `주유한눈 돌봄한눈식 모바일 지도 집중모드 적용`
- `치매안심 모바일 지도 전체모드 적용`

## 2. 핵심 UX

### A. 마커 선택 즉시 — 지도 집중 상세모드

모바일에서 마커를 누르면 별도 페이지로 이동하지 않고 **현재 지도 화면 위에 상세 패널을 열면서 지도 집중모드로 즉시 전환**한다.

기본 구성:

1. 지도는 화면 배경으로 계속 유지한다.
2. 선택 마커는 중앙 또는 가시영역 상단 쪽으로 재배치하여 상세 패널에 가리지 않게 한다.
3. 선택 마커는 일반 마커보다 명확히 강조한다.
4. 상세 패널은 화면 하단에서 올라오는 sheet/panel 형태로 표시한다.
5. 상세 패널 상단에는 핵심 정보와 닫기 버튼을 둔다.
6. 상세 패널은 내부 스크롤을 사용하고, 지도 자체는 화면 뒤에서 상태를 유지한다.
7. 상세를 닫으면 이전 지도 중심/배율/필터/선택 상태를 자연스럽게 복원한다.
8. 데스크톱 UX를 억지로 모바일에 축소하지 않는다.

### B. 상세 패널의 1차 상태 — compact focus

마커 선택 직후에는 **브라우저 페이지 일부가 아니라 전체 모바일 뷰포트를 지도가 차지하는 지도 집중 상태**로 즉시 전환하고, 하단 sheet가 함께 열린다.

필수 동작:
- 선택 마커 바로 위/근처에 **선택 항목 이름 팝업(callout)** 을 반드시 표시한다. 선택 마커만 강조하고 이름 팝업이 사라지는 구현은 완료로 보지 않는다.
- 팝업에는 최소 이름과 선택 상태가 보여야 하며, 서비스에 따라 가격/평점/사건번호 등 핵심 한 값을 함께 표시할 수 있다.
- 선택 마커와 팝업은 하단 sheet에 가리지 않는 지도 가시 영역에 유지한다.
- 1단계에서는 지도 조작 도구를 최소화한다. 현재위치, 확대/축소처럼 즉시 필요한 도구만 노출하고 검색/필터/레이어/전체화면 같은 고급 도구는 다음 단계에서 노출하는 것을 기본값으로 한다.
- 하단 sheet 상단에는 눈에 보이는 drag handle, `핵심 정보`, `상세 크게`, 닫기 버튼을 둔다.

마커 선택 직후에는 정보 집중 상태로 시작한다.

- 헤더/불필요한 목록/광고/보조 UI는 가능한 한 접는다.
- 지도는 상단에 충분히 노출한다.
- 상세 패널은 약 55~75% 화면 높이를 기본값으로 사용하되 콘텐츠와 기기 높이에 따라 조정한다.
- 패널 상단에는 `핵심 정보`, `상세 크게`, `닫기`와 같은 명확한 조작을 둔다.
- 핵심 정보 카드, 비교 담기, 즐겨찾기 등 서비스에 필요한 주요 액션을 첫 화면에서 노출한다.
- 주소/전화/길안내/공유 등 즉시 행동 가능한 정보는 탭 한두 번 안에 접근 가능해야 한다.

### C. `상세 크게` / 확장 상태 — staged tools

1단계와 2단계에서 **아이콘/도구가 단계적으로 노출되는 것 자체가 핵심 UX**다. 처음부터 모든 도구를 한꺼번에 보여 주지 않는다.

기본 단계:
- compact focus: 선택 팝업 + 선택 마커 + 하단 핵심정보 sheet + 현재위치/zoom 중심
- expanded tools: 검색창 + 카테고리/유종 + 필터 + 지도유형/레이어 + 전체지도 + 서비스별 추가 도구
- full-map: sheet를 최소화/숨기고 지도 자체에 집중하되 선택 마커/팝업은 유지

### D. 드래그 핸들 실제 동작

drag handle은 장식용 막대가 아니다. 포인터/터치 드래그로 상태가 실제 전환되어야 한다.

권장 snap:
- 아래쪽 snap: compact focus
- 위쪽 snap: expanded tools
- 더 아래로 충분히 끌기: 상세 닫기 또는 compact로 우선 복귀
- 위로 충분히 끌기: expanded tools
- 중간에서 놓기: 가장 가까운 snap으로 정렬

구현 규칙:
- `pointerdown / pointermove / pointerup` 또는 동등한 터치 처리를 사용한다.
- handle 영역에서 시작한 제스처는 지도 pan과 충돌하지 않게 한다.
- 드래그 중 sheet 높이/translate를 즉시 반영하고, 놓을 때 상태 모델을 확정한다.
- snap 후 지도 resize와 선택 마커 가시영역 보정을 다시 수행한다.
- 세로 이동 임계값과 velocity를 함께 고려할 수 있다.
- `prefers-reduced-motion`에서는 과한 spring animation을 쓰지 않는다.
- handle에는 접근 가능한 이름을 제공하고 버튼/키보드 동작으로도 compact↔expanded 전환이 가능해야 한다.

### E. 선택 마커 팝업

마커를 누르면 **마커 자체 강조 + 별도 popup/callout** 두 가지가 함께 보여야 한다.

- popup은 선택 항목 이름을 명확히 표시한다.
- 선택이 바뀌면 기존 popup은 닫히고 새 popup으로 교체한다.
- sheet 크기 전환/지도 resize 뒤에도 popup 위치가 선택 마커와 일치해야 한다.
- 지도 클릭 시 popup만 닫을지 상세 전체를 닫을지는 서비스 정책으로 정하되, 마커 재선택 시 다시 나타나야 한다.
- 모바일 집중모드에서는 popup이 sheet 뒤로 가려지지 않도록 z-index와 focus padding을 보정한다.
- Naver/Kakao/Leaflet의 실제 overlay/info window 또는 동등한 DOM overlay를 사용한다.

### F. `상세 크게` / 확장 상태

사용자가 상세 확장 버튼을 누르면 검색과 지도 도구를 함께 사용할 수 있는 **확장 지도모드**로 전환한다.

확장 상태에서 다음 도구를 필요에 따라 노출한다.

- 상단 검색창
- 카테고리 선택
- 필터
- 현재 위치
- 지도 확대/축소
- 지도 유형 전환
- 지도 전체화면/축소 아이콘
- 필요 시 목록 열기
- 서비스별 추가 지도 도구

중요: 모든 아이콘을 무조건 넣는 것이 아니라 해당 지도 SDK와 서비스 기능에 존재하는 도구만 노출한다. 다만 `현재 위치`, `검색`, `필터`, `지도 유형 전환`, `전체지도/복귀`는 지원 가능 여부를 반드시 검토한다.

### G. 지도 유형 전환

지도 SDK가 지원하면 기본 지도/위성 또는 항공/지형 등 적절한 지도 유형 전환 버튼을 제공한다.

- Naver Maps: 일반/위성 등 사용 가능한 유형
- Kakao Maps: 일반/스카이뷰 등
- Leaflet/OSM: 등록된 base layer 범위
- 제공하지 않는 기능을 가짜 버튼으로 만들지 않는다.

## 2-1. 공통 핵심 규칙 요약

이 절은 서비스 종류와 무관하게 모든 지도형 앱에 공통 적용하는 최소 기준이다. 서비스별 카드 구성, 색상, 도메인 필드는 이 기준 위에 별도로 확장한다.

### 공통 진입 규칙
- 모바일에서 사용자가 지도 마커를 선택하면 즉시 `focus-detail`로 진입한다.
- 진입 시 지도는 페이지 일부가 아니라 **전체 모바일 뷰포트의 배경**이 된다.
- 기존 지도 인스턴스, 중심 좌표, zoom, 필터, 선택 상태는 유지한다.
- 선택 마커와 popup은 하단 sheet에 가려지지 않도록 지도 중심 또는 padding을 보정한다.

### 공통 선택 마커 규칙
- 선택 마커는 일반 마커와 시각적으로 명확히 구분한다.
- 선택 마커에는 **이름 popup/callout을 반드시 함께 표시**한다.
- 선택 대상이 바뀌면 기존 popup은 교체한다.
- sheet 크기 변경, 지도 resize, 전체지도 전환 뒤에도 popup과 마커 정렬을 유지한다.

### 공통 단계형 상태
1. `default` — 지도 + 검색/목록 기본 상태
2. `focus-detail` — 선택 마커 + popup + compact bottom sheet + 최소 지도도구
3. `expanded-tools` — 검색/필터/지도유형/전체지도 등 추가 도구 노출
4. `full-map` — sheet를 최소화/숨기고 지도에 집중
5. `list` — 목록 중심
6. `dialog` — 별도 문서/사진/상세 모달

### 공통 단계별 도구 노출
- `focus-detail`: 현재위치, 확대/축소처럼 즉시 필요한 최소 도구만 노출한다.
- `expanded-tools`: 검색, 카테고리/유종, 필터, 지도유형/레이어, 전체지도, 서비스별 추가 도구를 노출한다.
- 처음부터 모든 아이콘을 노출하지 않는다.
- 지원하지 않는 SDK 기능은 가짜 버튼으로 만들지 않는다.

### 공통 bottom sheet 규칙
- 하단 sheet는 둥근 상단 모서리와 명확한 drag handle을 가진다.
- handle은 장식이 아니라 실제 드래그 동작을 수행한다.
- 위로 드래그하면 `expanded-tools`, 아래로 드래그하면 `focus-detail`로 전환한다.
- 충분히 아래로 드래그하면 닫기 또는 최소화 정책을 적용한다.
- 손을 놓으면 가장 가까운 snap 상태로 정렬한다.
- drag 중 map pan과 이벤트 충돌을 방지한다.

### 공통 상태 보존 규칙
- 집중모드 진입/확장/전체지도 전환 때문에 지도 객체를 새로 만들지 않는다.
- center, zoom, 필터, 선택 마커, 목록 스크롤을 가능한 유지한다.
- 닫기 후 사용자가 보던 기본 화면으로 자연스럽게 복원한다.
- 상세 중 사용자가 직접 지도를 이동했다면 과거 중심으로 강제 복귀하지 않는다.

### 공통 모바일 UI 규칙
- `100dvh`, safe-area를 고려한다.
- sheet 내부 스크롤과 페이지 스크롤을 분리한다.
- 검색창, 지도 조작 버튼, sheet가 서로 겹치지 않게 z-index를 설계한다.
- 360~430px 폭, 작은 높이, Android Chrome, iOS Safari를 점검한다.
- `prefers-reduced-motion`을 존중한다.

### 공통 접근성 규칙
- 아이콘 버튼에는 aria-label을 둔다.
- `aria-expanded`, `aria-pressed` 상태를 실제 UI 상태와 동기화한다.
- drag handle은 키보드/버튼으로도 compact↔expanded 전환이 가능해야 한다.
- Esc, 뒤로가기, 닫기, 포커스 복원을 안정적으로 처리한다.
- 터치 영역은 44px 이상을 권장한다.

### 공통 완료 판정
아래가 모두 실제로 동작해야 완료로 본다.

1. 마커 선택 즉시 전체 뷰포트 지도 집중 상태 진입
2. 선택 마커 강조
3. 선택 이름 popup 표시
4. compact bottom sheet 표시
5. drag handle 실제 동작
6. compact와 expanded의 도구 노출 차이 존재
7. expanded에서 검색/필터/지도유형/전체지도 지원 범위 확인
8. 지도유형 버튼이 실제 SDK 기능과 연결
9. sheet 전환 뒤 선택 마커가 가려지지 않음
10. 닫기/뒤로가기/다른 마커 연속 선택 정상 동작
11. center/zoom/filter/selection/list scroll 보존
12. 빌드/테스트/실제 운영 배포 확인

### 서비스별 확장 분리 원칙
다음은 전역 공통 규칙에 넣지 않고 각 서비스에서 확장한다.

- 카드의 데이터 필드
- 가격/평점/사건번호 등 도메인 핵심값
- 마커 색상 의미
- 브랜드 컬러
- 탭 구성
- 사진/문서/비교/찜 같은 서비스별 액션
- 특정 API나 수집 데이터 구조

전역 표준은 **상태 전환, 지도/마커/popup/sheet 상호작용, 단계형 도구 노출, 복원/접근성/성능**을 책임지고, 도메인 정보는 개별 앱이 책임진다.

## 3. 화면 상태 모델

모바일 지도 UI는 최소 다음 상태를 분리한다.

| 상태 | 설명 |
|---|---|
| `default` | 지도 + 목록/검색 기본 화면 |
| `focus-detail` | 마커 선택 직후 지도 집중 + 상세 패널 |
| `expanded-tools` | 상세 확장 + 검색/필터/지도도구 노출 |
| `full-map` | 상세 패널을 최소화하거나 접고 지도 자체를 최대화 |
| `list` | 목록 비교에 집중 |
| `dialog` | 사진/문서/법원정보 등 별도 상세 모달 |

상태 전환은 DOM 전체를 새로 만들기보다 기존 지도 인스턴스를 유지하는 방향을 우선한다.

## 4. 지도 인스턴스 유지 규칙

전체화면이나 상세모드 전환 때문에 지도 객체를 새로 생성하지 않는다.

- 동일 지도 DOM/인스턴스를 유지한다.
- 레이아웃 변경 뒤 SDK별 resize/invalidate를 호출한다.
- 중심 좌표와 zoom을 보존한다.
- 선택 마커와 필터를 보존한다.
- 전환 중 비동기 지도 이동이 발생하면 사용자의 최신 이동/선택을 우선한다.
- 마커 렌더링을 통째로 재생성하지 않아도 되는 경우 기존 오버레이를 재사용한다.

## 5. 선택 마커 가시성

상세 패널이 올라와도 선택한 마커가 가려지지 않게 한다.

구현 우선순위:

1. 패널 예상 높이만큼 map padding을 적용한다.
2. SDK가 padding을 지원하지 않으면 선택 마커 좌표를 화면 상단 가시영역으로 pan한다.
3. 선택 마커가 이미 충분히 보이면 불필요한 이동을 하지 않는다.
4. 닫을 때 원래 중심을 무조건 강제로 복귀하지 않는다. 사용자가 상세 중 지도를 움직였다면 최신 사용자 위치를 유지한다.

## 6. 모바일 상세 패널

- `position: fixed` 또는 지도 컨테이너 내부 absolute sheet를 사용한다.
- `100dvh`, `env(safe-area-inset-*)`를 고려한다.
- 패널 자체 스크롤과 페이지 스크롤이 충돌하지 않게 한다.
- drag handle 사용 시 map pan과 이벤트 충돌을 방지한다.
- 스크롤 가능한 상세 내용 아래에서도 닫기/핵심 액션 접근성이 유지되어야 한다.
- 키보드/입력창이 올라올 때 검색창과 하단 액션이 가려지지 않도록 visual viewport를 고려한다.

## 7. 모바일 마커 선택 시 자동 동작

마커 클릭 이벤트에서 다음을 순서대로 처리한다.

1. 선택 ID 저장
2. 상세 데이터 준비
3. 모바일 여부 확인
4. `focus-detail` 상태 진입
5. 지도 resize
6. 선택 마커 가시영역 보정
7. 상세 패널 표시
8. 상세 데이터 비동기 보강
9. 필요 시 URL/hash/history에 선택 상태 반영

상세 데이터 로딩이 느리면 패널 자체는 먼저 열고 skeleton/loading 상태를 보여준다.

## 8. 아이콘과 컨트롤 배치

돌봄한눈 기준의 원칙:

- 검색은 화면 상단
- 카테고리/필터는 검색창 아래
- 현재위치/zoom은 좌측 또는 지도 SDK 기본 위치
- 지도 유형/전체화면은 우측
- 상세 sheet는 하단
- 선택 마커는 sheet 위쪽 지도 영역에 남긴다.

서비스별 UI 색상/브랜드는 유지하되 조작 위치와 역할은 일관되게 한다.

## 9. 경매한눈 적용 시 추가 요구

경매한눈에서 이 표준을 적용할 때는 상세 패널에 다음을 우선한다.

- 사건번호
- 물건종류
- 소재지
- 감정가 / 최저가 / 유찰 횟수
- 매각기일
- 법원
- 사진 대표 썸네일
- 관심/비교 담기
- 상세 보기
- 길찾기 / 주소복사 / 공유
- 토지·건물·면적·점유/임차 등 확보된 핵심정보
- 법원/공식 원문 연결

사진이 확보되어 있다면 상세 패널 상단 또는 핵심정보 바로 아래에 대표 이미지를 표시하고, 좌우 탐색 가능한 갤러리로 확장한다.

## 10. 데이터 부족 시 원칙

UI만 돌봄한눈처럼 만들고 데이터가 없는 것을 임의로 채우지 않는다.

- 실제 수집 가능한 필드는 표시
- 미수집 필드는 `정보 없음`으로 구분
- 사진 미수집이면 placeholder보다 `사진 미수집`을 명확히 표시
- 공식 데이터/수집 데이터/추론값을 구분
- 추가 크롤링이나 API 연계가 필요하면 데이터 수집 작업을 별도 단계로 구현한다.

## 11. 접근성

- 모든 아이콘 버튼에 aria-label
- sheet는 적절한 heading 구조 사용
- 선택 마커는 키보드 포커스 지원 가능 여부 검토
- Esc: 최상위 열린 dialog → 확장 상태 → focus-detail 순으로 닫기
- 포커스 복원
- `aria-expanded`, `aria-pressed` 등 상태 반영
- 44px 이상 터치 영역 권장

## 12. 성능

- 마커 클릭마다 전체 마커 재생성 금지
- 상세 API 호출은 선택 물건/기관 중심으로 지연 로딩
- 이미지 lazy-load
- 상세 패널 스크롤 시 지도 리렌더 최소화
- ResizeObserver 이벤트는 frame 단위로 병합
- 모바일 저사양 기기에서도 지도 이동이 끊기지 않게 한다.

```text
대상 서비스에 돌봄한눈식 모바일 지도 집중모드를 적용해.

기준 UX:
- 모바일에서 지도 마커를 선택하면 즉시 지도 집중 상세모드로 들어간다.

- 상세 패널은 100dvh와 safe-area를 대응하고 내부 스크롤을 사용한다.
- 닫기/Esc/뒤로가기/다른 마커 연속 선택을 안정적으로 처리한다.
- 기존 데스크톱 UX는 깨뜨리지 않는다.
- 모바일 성능을 위해 지도 인스턴스와 마커 오버레이를 가능한 재사용한다.
- 서비스 고유 상세정보를 핵심정보/상세정보로 나누고, 사진이 있으면 대표 이미지와 갤러리를 연결한다.

작업 방식:
1. 현재 저장소의 지도/상세/모바일 구조를 먼저 확인한다.
2. 돌봄한눈 구현에서 재사용 가능한 패턴을 비교한다.
3. 서비스 구조에 맞게 상태 모델(default/focus-detail/expanded-tools/full-map/list/dialog)을 적용한다.
4. 실제 소스를 수정한다.
5. 모바일 회귀 테스트를 추가한다.
6. 빌드/테스트를 실행한다.
7. GitHub에 push한다.
8. 운영 배포까지 확인한다.
9. 완료 후 적용 파일, 커밋, 운영 URL, 모바일 동작 체크 결과를 보고한다.
```

## 18. 2026-10-23 승인 시안 기반 시각 디자인 표준

지도 집중모드는 상태 전환 기능뿐 아니라 **마커·팝업·도구·sheet의 시각 완성도**까지 포함한다. 기준 화면은 돌봄한눈식 구조를 주유한눈에 맞게 재해석한 compact focus / expanded tools 2단계 시안이다.

### 18.1 일반 마커
- 작은 원형/핀 계열 마커를 사용한다.
- 내부에는 서비스 카테고리 아이콘을 흰색으로 표시한다. 주유 서비스는 주유기 아이콘을 기본으로 한다.
- 지도 위 식별성을 위해 흰색 외곽선과 그림자를 둔다.
- 색상은 서비스 의미에 따라 4~5개 계열로 제한한다.
  - blue `#347ee8`
  - green `#16a077`
  - orange `#ed9815`
  - red `#e44f5e`
  - slate `#718397`
- 색상 매핑은 브랜드/상태/카테고리 중 서비스에 가장 의미 있는 기준을 택하되 무작위로 보이지 않게 일관성을 유지한다.

### 18.2 선택 마커
- 선택 마커는 일반 마커와 크기·색상·정보 밀도가 명확히 달라야 한다.
- 기본 선택 색상은 선명한 blue `#2f7df6` 계열을 권장한다.
- 일반 마커보다 약 1.7~2.2배 크게 표시한다.
- 가격형 서비스에서는 선택 마커 중앙에 대표 가격 숫자를 크게 표시한다.
- 흰 외곽선 + 외부 glow/shadow를 사용해 위성/일반 지도 모두에서 식별 가능하게 한다.
- 선택 마커는 하단 sheet가 올라와도 지도 가시영역 중앙 또는 상단 쪽에 남아야 한다.

### 18.3 선택 callout
- 선택 마커 위에 별도 흰색 callout을 항상 표시한다.
- 기본 구성: 카테고리 아이콘 + 항목명 + chevron.
- callout은 둥근 사각형, 얇은 경계, 그림자, 마커 방향 꼬리를 사용한다.
- callout은 단순 label이 아니라 선택 대상임을 명확히 보여주는 고정 오버레이다.
- compact/expanded 전환, resize, pan 이후에도 선택 마커와 함께 재배치한다.

### 18.4 compact focus 배치
- 지도는 전체 뷰포트 배경.
- 좌측 세로 도구: 현재위치 / 확대 / 축소.
- 선택 마커 + callout.
- 하단 rounded sheet.
- sheet 상단: drag handle / `핵심 정보` / `상세 크게` / 닫기.
- 검색·필터·레이어·전체지도 고급 도구는 기본적으로 숨긴다.

### 18.5 expanded tools 배치
- 상단에 큰 rounded 검색창.
- 검색창 아래 선택 카테고리/유종 chip과 필터 chip.
- 좌측 현재위치 / 확대 / 축소 유지.
- 우측에 지도 유형/레이어와 전체지도 버튼을 원형 floating control로 노출.
- 하단 sheet와 선택 마커/callout은 유지한다.
- expanded는 단순히 sheet 높이만 커지는 상태가 아니라 **지도 도구가 추가 노출되는 상태**다.

### 18.6 하단 상세 sheet 콘텐츠
서비스별 핵심정보는 첫 화면에서 빠르게 비교할 수 있게 카드화한다.

주유 서비스 권장 구조:
1. 지역 · 카테고리 · 브랜드 breadcrumb
2. 주유소명
3. 브랜드/셀프 배지
4. `비교에 담기` / 다른 주유소
5. 휘발유 · 경유 · LPG 가격 카드
6. `기본정보 / 상세정보` 탭
7. 주소 · 길안내
8. 전화번호 · 전화 걸기
9. 운영시간
10. 주소 복사 · 공유 · 찜
11. 상세 탭에서 가격 기준시각/수집시각/시설/이동비 계산

데이터가 없으면 임의 값을 만들지 않고 `가격 미제공`, `운영시간 정보 미제공`처럼 명시한다.

### 18.7 색상
- primary green: `#0f6b57`
- soft green: `#e8f3ed`
- selected marker blue: `#2f7df6`
- diesel/secondary blue: `#347ee8`
- orange: `#ed9815`
- divider: `#e6ebe7`
- muted text: `#7b8b84`
- sheet: `#ffffff`

### 18.8 오버레이/드래그 핸들
- handle은 sheet 상단 중앙에 40~44px 길이로 명확히 보이게 한다.
- 실제 hit-area는 시각 막대보다 크게 잡아 최소 54×18px 이상을 권장한다.
- `touch-action:none` 등으로 지도 pan과 충돌하지 않게 한다.
- 드래그 중 sheet transform을 즉시 반영한다.
- compact → 위 drag → expanded.
- expanded → 아래 drag → compact.
- compact에서 충분히 아래로 drag → 닫기.
- snap 완료 후 지도 resize 및 선택 마커/callout 재보정 필수.

### 18.9 완료 판정 추가
다음 중 하나라도 빠지면 승인 시안 기반 지도 집중모드 구현 완료로 보지 않는다.
- 일반 마커가 서비스용 아이콘/색상 체계로 재설계되지 않음
- 선택 마커가 일반 마커와 거의 같음
- 선택 callout 없음
- 가격/핵심정보 카드 없음
- compact와 expanded의 컨트롤 노출 차이가 없음
- 드래그 핸들이 장식만 하고 실제 snap이 없음
- expanded에서 지도유형/전체지도 버튼이 실제 기능과 연결되지 않음


## 19. 2026-10-23 5단계 토글 상태 표준

지도 집중모드의 모바일 토글은 다음 5개 사용자 상태를 독립 상태로 다룬다.

| 단계 | 상태명 | 핵심 동작 |
|---|---|---|
| 1 | `focus-detail` | 마커 선택 직후 상세 sheet 표시 |
| 2 | `map-browse` | 상세 X로 닫은 뒤 선택 마커를 유지한 전체지도 탐색 상태 |
| 3 | `expanded-tools` | 상세 상태에서 `상세 크게`를 눌러 검색/필터/레이어/전체지도 도구까지 표시 |
| 4 | `list-sheet` | map-browse 하단 메뉴의 목록 버튼으로 목록 bottom sheet를 연 상태 |
| 5 | `list-sheet-expanded` | 목록 sheet 핸들을 위로 끌어 목록 영역을 크게 확장한 상태 |

### 19.1 상세 닫기 규칙
- 상세 sheet의 X는 기본 페이지로 복귀시키지 않는다.
- X를 누르면 선택 마커/선택 callout/지도 중심/zoom/filter를 유지하고 `map-browse`로 이동한다.
- `map-browse`에는 검색/필터/지도유형/전체화면 도구와 하단 메뉴 그룹을 표시할 수 있다.
- 브라우저 뒤로가기 또는 명시적 집중모드 종료에서만 기본 `default` 레이아웃으로 복원한다.

### 19.2 map-browse 하단 메뉴 그룹
권장 기본 구성:
- `목록 N`
- `비교/담은 항목 N`
- `더보기`

목록 수와 비교 수는 현재 필터/선택 상태와 실시간 동기화한다.
필요 시 하단 메뉴 위에 `이 지역 재검색` floating button을 둔다.

### 19.3 목록 sheet
- 목록은 기존 페이지 전체 레이아웃으로 복귀하지 않고 현재 지도 위 bottom sheet로 연다.
- compact list sheet는 화면 높이 약 35~50%를 권장한다.
- expanded list sheet는 약 70~85%를 권장한다.
- 검색/상세와 독립적인 drag handle을 가진다.
- compact에서 위 drag → expanded.
- expanded에서 아래 drag → compact.
- compact에서 충분히 아래 drag → map-browse로 닫기.
- 목록에서 항목 선택 → 해당 항목의 `focus-detail`로 전환한다.

### 19.4 지도 인스턴스 유지
5단계 전환 동안 지도 객체를 재생성하지 않는다.
- 선택 ID 유지
- callout 유지
- map center/zoom 유지
- filter 유지
- 목록 스크롤 유지
- sheet snap 후에만 resize/invalidate를 호출한다.

### 19.5 완료 판정
다음이 실제로 연속 동작해야 한다.
1. 마커 선택 → 상세
2. X → 상세만 닫히고 map-browse 유지
3. 상세 다시 열기/상세 크게 → expanded-tools
4. map-browse 하단 목록 버튼 → list-sheet
5. 목록 핸들 위 drag → list-sheet-expanded
6. 목록 핸들 아래 drag → list-sheet
7. 목록에서 주유소 선택 → focus-detail
8. 뒤로가기 → 집중모드 종료 및 원래 기본 레이아웃 복구


## 20. 운전 중 사용하는 지도 서비스의 기본 상태

주유소·충전소처럼 **이동 중 빠른 탐색이 핵심인 서비스**는 일반 정보형 지도보다 조작 단계를 줄인다.

### 기본 진입
- 모바일 첫 진입은 `map-browse` 전체지도 **확장 상태**를 기본으로 한다.
- 헤더/일반 목록 레이아웃을 먼저 보여 주지 않는다.
- 상단 검색, 핵심 카테고리/유종, 필터, 현재위치, 확대/축소, 지도유형, 목록 진입을 지도 위에 바로 제공한다.
- 사용자가 추가 조작 없이 즉시 주변 마커와 가격을 볼 수 있어야 한다.

### 축소 상태
- 확장/축소 토글로 `map-collapsed` 상태를 제공한다.
- 축소 상태에서는 검색·필터·레이어·목록 dock 등 보조 UI를 숨긴다.
- 지도와 현재위치/확대/축소처럼 운전 중 즉시 필요한 조작만 남긴다.
- 다시 확장할 수 있는 단일 아이콘 버튼은 항상 접근 가능해야 한다.

### 상세 상태
- 마커 선택 시 `focus-detail`로 진입한다.
- 상세 헤더의 `상세 크게` 버튼에는 텍스트뿐 아니라 확장 아이콘을 함께 표시한다.
- 상세를 닫으면 이전 지도 확장/축소 상태로 복귀한다.
- 핵심 행동은 가격 확인, 길안내, 전화, 주소 확인 순으로 우선한다.

### 제거/후순위 기능
운전 중 여러 값을 입력해야 하는 계산형 기능은 기본 탐색 흐름에 두지 않는다.
- 출발지/목적지 직접 입력
- 주유량/연비/시간가치 입력
- 경유 경로 비용 비교
- 복잡한 절약액 계산

이런 기능이 별도 분석 도구로 필요하더라도 지도 탐색의 1차 UI와 분리한다.
