# 공통 계정·사이트별 정보 보관소

한눈·해요 운영 서비스는 [공통 모듈 원본](../../../services/suite-platform/README.md)과 `/shared/platform/v1/` SDK를 재사용한다. UID는 통합하고 사이트별 데이터 경로·인증 claim·암호문은 분리한다.

- 공통 화면: https://softm.github.io/account/
- 원본: https://github.com/softm/softm.github.io/tree/main/services/suite-platform
- 공통 모듈이 존재한다고 모든 사이트 적용·운영 로그인 검증이 끝난 것으로 보고하지 않는다.
- SNS 로그인은 SNS 자료 수집 동의가 아니다. 개인 기록 평문·복호화 암호·OAuth 비밀값을 저장소에 넣지 않는다.
- 기존 Firebase 프로젝트의 계정·자료를 사용자 확인 없이 교체하거나 이메일만으로 자동 병합하지 않는다.
- 위로해요의 기기 내 분석과 암호화 원칙은 유지한다.

## 회원가입·로그인과 사이트 정책 분리 (2026-10-29)

- 사이트의 기본 계정 진입은 로그인·회원가입이다. 보관소 열기나 복호화 암호를 로그인 조건으로 요구하지 않는다.
- SNS 인증과 회원가입은 구분한다. 최초 인증 후 가입 안내를 표시하고 명시적인 약관 동의 뒤 회원을 생성한다. 기존 회원은 로그인한다.
- 공통 인증은 UID와 사이트 범위 세션만 제공한다. 동기화 대상·시점·충돌·보관·삭제 정책은 사이트가 소유한다. 로그인 이벤트만으로 기기 자료를 업로드하지 않는다.
- 내 보관소는 별도 링크의 선택적 관리 기능이다. 기존 암호화 백업은 계속 읽을 수 있어야 한다. 기존 계정은 자동 병합하지 않는다.

## 상단 계정 아이콘 메뉴 (2026-10-30)

- 공통 진입점은 상단 원형 사용자 아이콘 하나다. 로그인·회원가입 버튼을 헤더에 나란히 펼쳐 놓지 않는다.
- 아이콘을 누르면 메뉴를 연다. 비로그인은 로그인·회원가입, 로그인 후에는 본인 프로필·계정 관리·로그아웃·회원탈퇴를 제공한다.
- Firebase `photoURL`, 제공자 `providerData[].photoURL`의 실제 프로필 이미지를 사용한다. 사진 미제공·허용되지 않은 URL·로딩 실패는 이름 첫 글자 또는 기본 사용자 아이콘으로 대체한다. 가짜 얼굴을 만들지 않는다.
- 계정 복원 중에는 진행 상태를 표시한다. 로그인/로그아웃은 중복 요청을 막고 팝업 차단·취소·실패를 표시한다.
- 메뉴는 본문 포털에서 표시해 지도/헤더의 overflow·transform에 가리지 않도록 한다. 작은 화면과 visualViewport 안으로 위치를 보정한다.
- 바깥 클릭, Escape, 키보드 탐색, 안전한 이미지 URL, reduced-motion, 해제 시 이벤트/관찰자 정리를 제공한다.
- 내 보관소는 메뉴 내부의 별도 선택 기능이다. 로그인과 메뉴 열기는 백업·복원을 자동 실행하지 않는다.
- 구현: `/shared/platform/v1/account-menu.mjs`, `/shared/platform/v1/account-menu.css`. 기존 `mountSiteAccount` 진입점으로 연결한다.
- 기존 연결 사이트는 공통 모듈 배포로 UI가 갱신된다. 날씨한눈의 별도 프록시 메뉴와 위로해요의 전용 어댑터는 별도로 통합해야 한다. 등록되지 않은 앱·오프라인 Android 패키지는 적용 완료로 간주하지 않는다.
- 합성 UI 검사는 실제 SNS 계정 및 모든 운영 사이트 검증을 대체하지 않는다. 카카오·네이버 프로필의 서버 저장과 운영 배포는 별도 확인한다.
