# 모바일 지도 집중모드 전역 표준

최종 갱신: 2026-10-22

이 문서는 지도 중심 웹앱에서 모바일 사용자가 마커를 선택하거나 지도를 넓혀 보고 싶을 때 적용하는 공통 UX/구현 기준이다. 기준 UX는 돌봄한눈의 모바일 지도 상세 흐름이다.

## 1. 호출 키워드

다음 표현은 모두 같은 작업 지시로 해석한다.

- `돌봄한눈식 모바일 지도 집중모드 적용`
- `지도 집중모드 적용`
- `돌봄한눈 지도모드 적용`
- `모바일 지도 전체모드 적용`
- `돌봄한눈처럼 마커 상세 + 전체지도`

사용자가 서비스명과 함께 위 표현을 말하면, 별도 기획 설명만 하지 말고 해당 서비스의 실제 지도 UI와 상태 관리 구조를 확인한 뒤 가능한 범위에서 소스 수정, 테스트, 푸시, 배포 검증까지 진행한다.

예:
- `경매한눈 지도 집중모드 적용`
- `주유한눈 돌봄한눈식 모바일 지도 집중모드 적용`
- `치매안심 모바일 지도 전체모드 적용`

## 2. 핵심 UX

### A. 마커 선택 즉시 — 지도 집중 상세모드

모바일에서 마커를 누르면 별도 페이지로 이동하지 않고 **현재 지도 화면 위에 상세 패널을 열면서 지도 집중모드로 즉시 전환**한다.

기본 구성:

1. 지도는 화면 배경으로 계속 유지한다.
2. 선택 마커는 중앙 또는 가시영역 상단 쪽으로 재배치하여 상세 패널에 가리지 않게 한다.
3. 선택 마커는 일반 마커보다 명확히 강조한다.
4. 상세 패널은 화면 하단에서 올라오는 sheet/panel 형태로 표시한다.
5. 상세 패널 상단에는 핵심 정보와 닫기 버튼을 둔다.
6. 상세 패널은 내부 스크롤을 사용하고, 지도 자체는 화면 뒤에서 상태를 유지한다.
7. 상세를 닫으면 이전 지도 중심/배율/필터/선택 상태를 자연스럽게 복원한다.
8. 데스크톱 UX를 억지로 모바일에 축소하지 않는다.

### B. 상세 패널의 1차 상태

마커 선택 직후에는 정보 집중 상태로 시작한다.

- 헤더/불필요한 목록/광고/보조 UI는 가능한 한 접는다.
- 지도는 상단에 충분히 노출한다.
- 상세 패널은 약 55~75% 화면 높이를 기본값으로 사용하되 콘텐츠와 기기 높이에 따라 조정한다.
- 패널 상단에는 `핵심 정보`, `상세 크게`, `닫기`와 같은 명확한 조작을 둔다.
- 핵심 정보 카드, 비교 담기, 즐겨찾기 등 서비스에 필요한 주요 액션을 첫 화면에서 노출한다.
- 주소/전화/길안내/공유 등 즉시 행동 가능한 정보는 탭 한두 번 안에 접근 가능해야 한다.

### C. `상세 크게` / 확장 상태

사용자가 상세 확장 버튼을 누르면 검색과 지도 도구를 함께 사용할 수 있는 **확장 지도모드**로 전환한다.

확장 상태에서 다음 도구를 필요에 따라 노출한다.

- 상단 검색창
- 카테고리 선택
- 필터
- 현재 위치
- 지도 확대/축소
- 지도 유형 전환
- 지도 전체화면/축소 아이콘
- 필요 시 목록 열기
- 서비스별 추가 지도 도구

중요: 모든 아이콘을 무조건 넣는 것이 아니라 해당 지도 SDK와 서비스 기능에 존재하는 도구만 노출한다. 다만 `현재 위치`, `검색`, `필터`, `지도 유형 전환`, `전체지도/복귀`는 지원 가능 여부를 반드시 검토한다.

### D. 지도 유형 전환

지도 SDK가 지원하면 기본 지도/위성 또는 항공/지형 등 적절한 지도 유형 전환 버튼을 제공한다.

- Naver Maps: 일반/위성 등 사용 가능한 유형
- Kakao Maps: 일반/스카이뷰 등
- Leaflet/OSM: 등록된 base layer 범위
- 제공하지 않는 기능을 가짜 버튼으로 만들지 않는다.

## 3. 화면 상태 모델

모바일 지도 UI는 최소 다음 상태를 분리한다.

| 상태 | 설명 |
|---|---|
| `default` | 지도 + 목록/검색 기본 화면 |
| `focus-detail` | 마커 선택 직후 지도 집중 + 상세 패널 |
| `expanded-tools` | 상세 확장 + 검색/필터/지도도구 노출 |
| `full-map` | 상세 패널을 최소화하거나 접고 지도 자체를 최대화 |
| `list` | 목록 비교에 집중 |
| `dialog` | 사진/문서/법원정보 등 별도 상세 모달 |

상태 전환은 DOM 전체를 새로 만들기보다 기존 지도 인스턴스를 유지하는 방향을 우선한다.

## 4. 지도 인스턴스 유지 규칙

전체화면이나 상세모드 전환 때문에 지도 객체를 새로 생성하지 않는다.

- 동일 지도 DOM/인스턴스를 유지한다.
- 레이아웃 변경 뒤 SDK별 resize/invalidate를 호출한다.
- 중심 좌표와 zoom을 보존한다.
- 선택 마커와 필터를 보존한다.
- 전환 중 비동기 지도 이동이 발생하면 사용자의 최신 이동/선택을 우선한다.
- 마커 렌더링을 통째로 재생성하지 않아도 되는 경우 기존 오버레이를 재사용한다.

## 5. 선택 마커 가시성

상세 패널이 올라와도 선택한 마커가 가려지지 않게 한다.

구현 우선순위:

1. 패널 예상 높이만큼 map padding을 적용한다.
2. SDK가 padding을 지원하지 않으면 선택 마커 좌표를 화면 상단 가시영역으로 pan한다.
3. 선택 마커가 이미 충분히 보이면 불필요한 이동을 하지 않는다.
4. 닫을 때 원래 중심을 무조건 강제로 복귀하지 않는다. 사용자가 상세 중 지도를 움직였다면 최신 사용자 위치를 유지한다.

## 6. 모바일 상세 패널

- `position: fixed` 또는 지도 컨테이너 내부 absolute sheet를 사용한다.
- `100dvh`, `env(safe-area-inset-*)`를 고려한다.
- 패널 자체 스크롤과 페이지 스크롤이 충돌하지 않게 한다.
- drag handle 사용 시 map pan과 이벤트 충돌을 방지한다.
- 스크롤 가능한 상세 내용 아래에서도 닫기/핵심 액션 접근성이 유지되어야 한다.
- 키보드/입력창이 올라올 때 검색창과 하단 액션이 가려지지 않도록 visual viewport를 고려한다.

## 7. 모바일 마커 선택 시 자동 동작

마커 클릭 이벤트에서 다음을 순서대로 처리한다.

1. 선택 ID 저장
2. 상세 데이터 준비
3. 모바일 여부 확인
4. `focus-detail` 상태 진입
5. 지도 resize
6. 선택 마커 가시영역 보정
7. 상세 패널 표시
8. 상세 데이터 비동기 보강
9. 필요 시 URL/hash/history에 선택 상태 반영

상세 데이터 로딩이 느리면 패널 자체는 먼저 열고 skeleton/loading 상태를 보여준다.

## 8. 아이콘과 컨트롤 배치

돌봄한눈 기준의 원칙:

- 검색은 화면 상단
- 카테고리/필터는 검색창 아래
- 현재위치/zoom은 좌측 또는 지도 SDK 기본 위치
- 지도 유형/전체화면은 우측
- 상세 sheet는 하단
- 선택 마커는 sheet 위쪽 지도 영역에 남긴다.

서비스별 UI 색상/브랜드는 유지하되 조작 위치와 역할은 일관되게 한다.

## 9. 경매한눈 적용 시 추가 요구

경매한눈에서 이 표준을 적용할 때는 상세 패널에 다음을 우선한다.

- 사건번호
- 물건종류
- 소재지
- 감정가 / 최저가 / 유찰 횟수
- 매각기일
- 법원
- 사진 대표 썸네일
- 관심/비교 담기
- 상세 보기
- 길찾기 / 주소복사 / 공유
- 토지·건물·면적·점유/임차 등 확보된 핵심정보
- 법원/공식 원문 연결

사진이 확보되어 있다면 상세 패널 상단 또는 핵심정보 바로 아래에 대표 이미지를 표시하고, 좌우 탐색 가능한 갤러리로 확장한다.

## 10. 데이터 부족 시 원칙

UI만 돌봄한눈처럼 만들고 데이터가 없는 것을 임의로 채우지 않는다.

- 실제 수집 가능한 필드는 표시
- 미수집 필드는 `정보 없음`으로 구분
- 사진 미수집이면 placeholder보다 `사진 미수집`을 명확히 표시
- 공식 데이터/수집 데이터/추론값을 구분
- 추가 크롤링이나 API 연계가 필요하면 데이터 수집 작업을 별도 단계로 구현한다.

## 11. 접근성

- 모든 아이콘 버튼에 aria-label
- sheet는 적절한 heading 구조 사용
- 선택 마커는 키보드 포커스 지원 가능 여부 검토
- Esc: 최상위 열린 dialog → 확장 상태 → focus-detail 순으로 닫기
- 포커스 복원
- `aria-expanded`, `aria-pressed` 등 상태 반영
- 44px 이상 터치 영역 권장

## 12. 성능

- 마커 클릭마다 전체 마커 재생성 금지
- 상세 API 호출은 선택 물건/기관 중심으로 지연 로딩
- 이미지 lazy-load
- 상세 패널 스크롤 시 지도 리렌더 최소화
- ResizeObserver 이벤트는 frame 단위로 병합
- 모바일 저사양 기기에서도 지도 이동이 끊기지 않게 한다.

## 13. 구현 완료 기준

다음을 실제 확인해야 완료로 본다.

1. 모바일 마커 선택 즉시 focus-detail 진입
2. 선택 마커가 상세 패널에 가려지지 않음
3. 상세 크게/축소 동작
4. 검색/필터/현재위치/지도유형 등 필요한 도구 노출
5. 지도 전체모드 진입/복귀
6. 지도 center/zoom/filter 보존
7. 상세 닫기/다른 마커 선택 연속 동작
8. 브라우저 뒤로가기 또는 앱 내 복귀 처리
9. Android Chrome / iOS Safari 계열 safe-area 확인
10. 360~430px 폭, 작은 높이, 가로모드 점검
11. 빌드/테스트 통과
12. 저장소 push
13. 실제 운영 배포 확인
14. 캐시된 이전 탭과 새 배포를 구분하여 검증

## 14. 작업 지시용 전체 프롬프트

```text
대상 서비스에 돌봄한눈식 모바일 지도 집중모드를 적용해.

기준 UX:
- 모바일에서 지도 마커를 선택하면 즉시 지도 집중 상세모드로 들어간다.
- 현재 지도 인스턴스는 유지하고, 선택 마커가 상세 패널에 가리지 않도록 지도 중심/padding을 조정한다.
- 하단에는 상세 sheet를 띄운다.
- 첫 상태는 핵심 정보 중심이며, 상세 크게/닫기/비교 또는 서비스 핵심 액션을 제공한다.
- 상세 크게를 누르면 상단 검색, 카테고리, 필터와 지도 도구를 노출한다.
- 현재위치, 확대/축소, 지도유형 전환, 전체지도/복귀를 해당 지도 SDK가 지원하는 범위에서 제공한다.
- 지도유형 버튼은 실제 SDK 기능과 연결하고 가짜 기능은 만들지 않는다.
- 전체지도/상세확장/목록 간 이동에서 center, zoom, 필터, 선택 항목, 목록 스크롤을 보존한다.
- 상세 패널은 100dvh와 safe-area를 대응하고 내부 스크롤을 사용한다.
- 닫기/Esc/뒤로가기/다른 마커 연속 선택을 안정적으로 처리한다.
- 기존 데스크톱 UX는 깨뜨리지 않는다.
- 모바일 성능을 위해 지도 인스턴스와 마커 오버레이를 가능한 재사용한다.
- 서비스 고유 상세정보를 핵심정보/상세정보로 나누고, 사진이 있으면 대표 이미지와 갤러리를 연결한다.
- 없는 데이터는 임의 생성하지 말고 미수집/정보없음을 구분한다.

작업 방식:
1. 현재 저장소의 지도/상세/모바일 구조를 먼저 확인한다.
2. 돌봄한눈 구현에서 재사용 가능한 패턴을 비교한다.
3. 서비스 구조에 맞게 상태 모델(default/focus-detail/expanded-tools/full-map/list/dialog)을 적용한다.
4. 실제 소스를 수정한다.
5. 모바일 회귀 테스트를 추가한다.
6. 빌드/테스트를 실행한다.
7. GitHub에 push한다.
8. 운영 배포까지 확인한다.
9. 완료 후 적용 파일, 커밋, 운영 URL, 모바일 동작 체크 결과를 보고한다.

기획서만 작성하고 멈추지 말고 실제 구현과 검증까지 진행한다.
```

## 15. 기본 해석 규칙

사용자가 단순히 `지도 집중모드 적용`이라고 말하면 위 전체 프롬프트를 축약 호출한 것으로 간주한다.

서비스명이 함께 있으면 그 서비스에 바로 적용한다.

예:
`경매한눈 지도 집중모드 적용`

→ 경매한눈 저장소 확인 → 돌봄한눈 모바일 UX 비교 → 실제 구현 → 테스트 → push → 배포 검증까지 수행한다.
