# 웹 배포 프로젝트 인덱스 운영 규칙

`https://softm.github.io/projects/`는 프로젝트별 공개·비공개 웹 배포의 상태, 링크와 간단한 설명을 모으는 중앙 인덱스다.

## 기본 원칙

- **GitHub 프로젝트 저장소를 Source of Truth로 사용한다.**
- 개별 페이지를 변경하면 같은 작업 단위에서 **프로젝트 홈**과 **최상위 `softm.github.io/projects/` 중앙 인덱스**를 함께 갱신한다.
- 저장소 반영만으로 완료 처리하지 않는다. 실제 운영 URL에서 최신 내용, 인증, 404, 리다이렉트 상태를 확인해야 한다.
- 공개/비공개라는 분류와 실제 익명 접근 가능 여부는 별도로 점검한다.
- `pageCount`, `privatePageCount`, 전체 배포 수, `채팅별 페이지 N개`, `latestTitle`은 실제 목록과 일치해야 한다.

## 배포 명령

- `웹 배포`: 해당 프로젝트의 공개 GitHub 저장소를 원본으로 공개 사이트에 배포한다.
- `비공개 웹 배포`: 같은 프로젝트의 `-private` 접미사 Private GitHub 저장소를 원본으로 인증된 Vercel 사이트에 배포한다.
- `지피트 웹 배포`: ChatGPT Sites와 ChatGPT 인증을 사용한다.
- `아카이브 배포`: 채팅별 정리 결과와 확보된 원본 자료를 프로젝트 저장소에 함께 보존하고 프로젝트 홈/중앙 인덱스까지 동기화한다.

## 공개 배포 기준

- 공개 저장소 이름은 기본적으로 `<project>` 또는 필요 시 `<project>-public`을 사용한다. `-public`은 필수가 아니다.
- 공개 콘텐츠의 원본은 **해당 프로젝트 공개 저장소**다.
- `softm.github.io` 메인 저장소에는 프로젝트 본문 콘텐츠를 원본으로 두지 않는다.
- `softm.github.io/projects/`는 중앙 인덱스 역할만 한다.
- 공개 프로젝트 홈은 익명 접근 가능한 실제 운영 URL이어야 한다.

## 비공개 배포 기준

- 비공개 저장소는 `<project>-private` Private GitHub 저장소를 사용한다.
- 비공개 운영 URL은 인증된 Vercel 사이트를 사용한다.
- 신규 HTML 보고서·아카이브는 가능한 한 **Vercel 서버가 GitHub API를 통해 `main` 최신 파일을 요청 시 읽는 방식**을 기본으로 한다.
- GitHub 요청은 `cache: no-store`로 처리한다.
- GitHub Token·비밀번호 검증값 등 인증정보는 클라이언트 HTML에 넣지 않고 서버 환경변수에서만 사용한다.
- 기존 빌드형 페이지가 있는 프로젝트는 깨뜨리지 않고 유지하되, 신규 보고서/아카이브부터 live 구조로 전환할 수 있다.
- GitHub push 자동배포를 사용하는 경우에도 운영 URL에서 실제 최신 반영을 확인해야 완료로 본다.

## 아카이브 배포

- 채팅별 디렉터리에 `index.html`과 `summary.md`를 저장한다.
- 채팅에 이미지가 있으면 실제 이미지 파일을 `images/`에 저장한다.
- PDF·문서·ZIP 등 기타 첨부파일이 있으면 실제 파일을 `files/`에 저장한다.
- 확보되지 않은 원본 파일은 임의로 만들거나 있다고 표시하지 않는다.
- 공개 아카이브는 해당 프로젝트의 공개 저장소를 원본으로 사용한다.
- 비공개 아카이브는 `<project>-private` Private GitHub 저장소를 원본으로 사용한다.
- 프로젝트 홈에서 채팅별 아카이브 페이지로 이동할 수 있어야 한다.
- 배포와 같은 작업 단위에서 중앙 인덱스도 갱신한다.

## 필수 동기화 규칙

다음 변경은 프로젝트 저장소 작업과 같은 작업 단위에서 반드시 `projects/projects.json`에 반영한다.

- 공개 또는 비공개 프로젝트 생성
- 프로젝트 삭제·보관·이름 변경
- 공개 URL 또는 인증 URL 변경
- 공개 → 비공개, 비공개 → 공개 전환
- 공개+비공개 병행 상태 변경
- 실제 배포 전·후의 `pending` ↔ `deployed` 상태 변경
- 프로젝트 홈 URL 생성·변경
- 공개/비공개 페이지 수 및 최근 페이지 변경

변경 후에는 중앙 인덱스에서 카드, 공개 여부, 링크와 상태가 실제로 보이는지 확인한다.

## 프로젝트 홈 연결 규칙

- 중앙 인덱스에서 프로젝트 카드를 누르면 개별 채팅 페이지가 아니라 **해당 프로젝트 홈**으로 이동해야 한다.
- 공개 프로젝트는 `homeUrl`과 `publicUrl`을 같은 공개 프로젝트 홈으로 맞춘다.
- 비공개 프로젝트는 `homeUrl`과 `privateUrl`을 인증 게이트가 있는 프로젝트 홈으로 맞춘다.
- 공개+비공개 병행 프로젝트는 **공개 홈을 `homeUrl`**로 두고 인증 홈은 `privateUrl`로 별도 표시한다.
- 전용 프로젝트 홈이 없거나 아직 검증되지 않았으면 `deploymentStatus`를 `pending`, `unverified`, `needsHome` 중 실제 상태에 맞게 표시한다.

## 공개 범위

- 공개 프로젝트는 공개 사이트와 공개 GitHub 저장소 링크를 표시한다.
- 비공개 프로젝트도 프로젝트명과 비공개 상태는 중앙 인덱스에 표시할 수 있다.
- 비공개 저장소 주소, 비밀번호, 원본 자료와 개인정보는 공개 인덱스에 노출하지 않는다.
- 인증 URL은 공개 인덱스에 표시해도 되는 주소만 `privateUrl`에 넣는다.
- 공개 사이트와 비공개 사이트가 모두 있으면 `visibility: "mixed"`로 표시한다.

## 실제 운영 검증

배포 완료 전 다음을 확인한다.

1. 프로젝트 홈 URL이 열리는가.
2. 공개 URL이 익명으로 열리는가.
3. 비공개 URL은 인증 없이 본문이 노출되지 않는가.
4. 404, 401, 로그인 요구, 불필요한 리다이렉트가 있는가.
5. 저장소 최신 변경이 운영 사이트에 실제 반영됐는가.
6. 프로젝트 홈과 중앙 인덱스의 공개/비공개 개수가 실제 목록과 같은가.

## `projects.json` 주요 필드

- `repo`: 중앙 인덱스용 프로젝트 식별자
- `title`: 화면 표시 프로젝트명
- `category`: 프로젝트 분류
- `description`: 간단한 설명
- `visibility`: `public`, `private`, `mixed`
- `repoVisibility`: `public`, `private`, `missing`
- `deploymentStatus`: `pending`, `deployed`, `unverified`, `needsHome`
- `homeUrl`: 중앙 인덱스 카드 클릭 기준 URL
- `publicUrl`: 실제 공개 프로젝트 홈 또는 공개 사이트
- `privateUrl`: 인증 프로젝트 홈
- `pageCount`, `privatePageCount`: 공개·비공개 채팅 페이지 수
- `latestTitle`: 최근 페이지 제목
- `order`: 표시 순서
