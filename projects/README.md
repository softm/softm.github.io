# 전역 아카이브 배포 규칙

기준 인덱스: https://softm.github.io/projects/

최종 갱신: 2026-10-05. 이 문서는 모든 프로젝트의 아카이브 작업에 적용한다.

## 0.1 2026-10-05 전체 초기화 기준

이번 전체 재정비는 사용자의 명시적 지시에 따라 **기존 아카이브 작성 콘텐츠를 현재 브랜치에서 모두 초기화하고 새 기준으로 처음부터 다시 작성하는 1회성 기준 전환**이다.

- GitHub 저장소 자체, Git 이력, GitHub Pages/Vercel 프로젝트 연결·도메인·워크플로·보호 설정 등 배포 기반은 유지한다.
- 기존 HTML/MD/목록/메타데이터/아카이브 생성물은 새 기준의 원본으로 재사용하지 않는다.
- 새 기록부터 아래의 공개/비공개 구조, Source of Truth, canonical date/title/slug/id, 미디어 포함, 프로젝트 홈·중앙 인덱스 동기화 및 실제 운영 검증 규칙을 적용한다.
- 아래의 “기존 콘텐츠 누적 보존” 규칙은 **2026-10-05 이후 새 기준으로 다시 등록되는 콘텐츠부터** 적용한다. 이번 초기화 작업에는 예외로 적용하지 않는다.

## 0. 사진·미디어 반드시 포함 — 모든 정리 작업의 기본값

사용자가 2026-09-30 재확정한 필수 기준: **사진 및 미디어는 반드시 포함해서 정리한다.** 사용자가 매번 "사진 포함", "영상 포함"을 덧붙이지 않아도 적용한다.

| 적용 대상 | 필수 처리 |
|---|---|
| 정리·재정리·md 정리·HTML·ZIP | 해당 기록에 첨부된 사진·영상·음성·녹취·문서·압축파일 안의 관련 자료를 먼저 전수 확인하고, 정리본과 묶음에 실제 파일을 포함한다. |
| 공개 배포·비공개 배포·아카이브 배포 | 파일명 목록이 아니라 실제 원본 파일을 저장소에 보존하고, 운영 문서에서 실제 표시·재생·다운로드되도록 연결한다. 공개 가능 여부와 인증 기준은 그대로 적용한다. |
| 사진 | 본문 또는 갤러리에 표시하고 원본 확대·열기·다운로드를 제공한다. 비슷한 사진도 임의로 제거하지 않는다. |
| 영상·음성 | 플레이어와 원본 다운로드를 제공한다. 호환성용 변환본은 원본과 별도 보관하며 원본을 덮어쓰거나 대체하지 않는다. |
| PDF 등 미디어 재생이 불가능한 문서 형식 | 관련 사진·대표 화면과 원본 접근 링크를 문서에 제공하고, 원본 미디어는 함께 제공하는 ZIP 또는 같은 접근 권한의 아카이브에 포함한다. |
| 원본 누락·전송 실패·확인 불가 | 대상 파일명·누락 개수·실패 단계·사유를 구분해 알린다. 텍스트만 배포한 상태를 사진·미디어 포함 완료라고 보고하지 않는다. |

작업 시작 시 원본 목록과 기대 개수를 확정한다. 각 원본의 파일명·유형·바이트 크기·SHA-256 및 정리본 참조 경로를 기록하고, **첨부 원본 → 정리 폴더 → ZIP → 저장소 → 실제 운영 URL**을 대조한다. 첨부 원본 목록 없이 현재 저장소에 있는 파일만 세어서 누락 0건으로 판단하지 않는다.

완료 조건은 다음 항목을 **각각 실제 실행하여 통과한 경우**다.

1. 해당 기록의 확보 가능한 원본이 빠짐없이 보존되어 있고 기존 상세 본문을 축약본으로 대체하지 않았다.
2. ZIP 내부의 실제 원본 개수와 해시가 첨부 원본과 일치한다.
3. HTML/MD의 상대 경로, 갤러리, 플레이어, 원본 다운로드가 실제 파일을 가리킨다.
4. 배포 요청이면 저장소 원본과 운영 파일의 바이트·해시, 사진 표시, 영상·음성 실제 재생을 확인한다. 페이지 HTTP 200이나 CI 성공만으로 통과 처리하지 않는다.
5. 프로젝트 홈과 전체 인덱스 연결이 맞고, 민감 원본은 공개 저장소·공개 다운로드에 노출되지 않는다.

통과하지 못한 항목은 미완료 또는 미검증이다. "원본 확보", "업로드", "웹 배포", "실제 표시·재생 검증"을 서로 구분해서 보고한다. 무관한 외부 서비스로 원본을 보내거나 새로운 저장소를 임의로 만들어 누락 문제를 우회하지 않는다.

이 문서는 프로젝트 간 공유 기준의 저장 위치다. 문서 수정이 모든 대화의 개인 메모리를 자동 갱신하거나 모든 기존 사이트를 자동 복구했다는 뜻은 아니다. 후속 작업은 이 기준을 읽고 해당 프로젝트에 실제로 적용·검증해야 한다.

## 1. 아카이브 배포의 의미

아카이브 배포는 **공개 배포와 비공개 배포를 포함하는 상위 개념**이다. 공개/비공개와 나란한 제3의 배포 방식이 아니다. 기존 프로젝트의 저장소와 운영 구조를 우선 재사용하고 별도 archive 저장소를 임의로 만들지 않는다.

사용자가 명확히 아카이브 배포를 지시하면 가능한 작업을 실제 실행한다. 저장소 커밋만 하고 운영 배포까지 완료됐다고 말하지 않는다.

## 2. 공개 정보와 비공개 자료의 이동 경로

**전체 인덱스 → 공개/비공개 GitHub 저장소 → 프로젝트 비밀번호 또는 Vercel 계정 인증 → 요청한 자료**

- 공개 프로젝트 정보의 원본은 **해당 프로젝트의 공개 GitHub 저장소**다. 공개 저장소 이름은 `<project>` 또는 기존 `<project>-public`을 사용한다.
- 공개 프로젝트 홈에는 공개 가능한 설명과 함께 **비공개 배포의 존재, 안전한 안내, 인증 링크**도 표시한다.
- 중앙 프로젝트 인덱스에는 사용자가 요청한 공개 GitHub 저장소와 Private GitHub 저장소 링크를 모두 표시한다. Private GitHub 링크는 GitHub 접근 권한이 있는 계정만 열 수 있다. 비밀번호, 토큰, 민감 원문과 원본 미디어 내용 자체는 공개 페이지에 노출하지 않는다.
- 비공개 운영 페이지는 두 인증 방식을 구분한다. `프로젝트 비밀번호 인증`은 애플리케이션 서버가 검증하는 자체 로그인이고, `Vercel 계정 인증`은 Vercel Deployment Protection이 제공하는 플랫폼 로그인이다. 둘을 같은 의미의 'Vercel 인증'으로 표시하지 않는다.
- 가능하면 두 보호 계층을 함께 사용할 수 있게 구성한다. Vercel Deployment Protection이 켜진 경우 먼저 Vercel 계정 인증을 통과한 뒤 프로젝트 자체 비밀번호 인증을 거칠 수 있다. Vercel 보호 설정이 꺼져 있으면 프로젝트 비밀번호만 실제 보호로 동작하므로 중앙 인덱스에 상태를 명시한다.
- 공개 HTML에 비밀번호 검증값을 넣거나 JavaScript로 화면만 가리는 방식은 인증으로 인정하지 않는다.
- 인증 후 처음 요청한 문서/사진/영상/음성으로 돌아가도록 안전한 returnTo 경로를 유지한다.
- 이미 인증된 세션은 추가 로그인 화면 없이 대상 페이지가 표시될 수 있다.
- 공개 안내가 없거나 아직 배포되지 않았으면 이를 명시한다. 저장소에 안내 소스가 생겼다고 웹 배포 완료로 표시하지 않는다.
- 기존 ChatGPT Sites 주소는 보존할 수 있지만 **Vercel 인증된 비공개 배포와 명확히 구별**한다.

중앙 `softm.github.io/projects/`는 안내·상태·링크를 모으는 인덱스다. 개별 프로젝트 본문을 중앙 저장소에 새 원본으로 복제하지 않는다.

## 3. 비공개 원본과 Vercel 역할

- 비공개 원본은 해당 `<project>-private` Private GitHub 저장소에 둔다. 기존 명칭이 다르면 기존 자료를 보호하면서 전환 계획을 기록한다.
- GitHub 저장소를 **유일한 아카이브 원본**으로 사용한다.
- Vercel은 서버 측 인증과 라우팅을 담당하고 서버 환경변수의 `GITHUB_TOKEN`으로 해당 GitHub 최신 파일을 요청 시 읽는다.
- 원본 요청과 응답은 `cache: no-store`, `Cache-Control: private, no-store`를 기준으로 한다.
- 인증정보는 서버에만 보관한다. 공개 저장소·클라이언트·URL·로그에 토큰이나 비밀번호를 쓰지 않는다.
- 비공개 HTML·MD·사진·영상·음성·문서·ZIP도 모두 동일한 인증 검사를 거쳐 제공한다. 루트뿐 아니라 직접 파일 주소를 점검한다.
- `.vercelignore`, 명시적 빌드 대상 또는 프레임워크 설정으로 원본 아카이브가 정적 배포물이나 별도 Vercel 사본으로 포함되지 않도록 확인한다.
- 기존 빌드형 애플리케이션은 근거 없이 파괴하지 않는다. 전환하지 못한 경로는 미전환으로 표시한다.
- GitHub 변경이 즉시 조회되는지와 서버 코드 변경 후 Vercel 운영 배포가 실제 최신 커밋인지 각각 확인한다.

## 4. 사진·미디어·첨부자료의 필수 보존

채팅별 디렉터리에는 가능한 한 `index.html`, `summary.md`를 함께 보관한다. 실제 이미지·영상·음성·녹취·PDF·문서·관련 ZIP 등 확보 가능한 원본을 빠짐없이 연결한다.

- 사진은 `images/`, 영상·음성은 `media/`, 기타 첨부는 `files/` 등 기존 구조를 존중하여 보관한다.
- 파일명 목록이나 manifest만 존재하면 **원본 포함 완료가 아니다**.
- 각 파일의 존재, 바이트 크기, 해시를 기록하고 HTML/MD의 실제 참조 경로를 대조한다.
- 갤러리·영상 재생기·음성 재생기·원본 열기 링크는 실제 파일을 가리켜야 한다.
- 한글·공백·Unicode 파일명, 상대 경로, 직접 파일 주소의 인증을 점검한다.
- 영상·음성은 파일 크기와 호스팅 한도를 확인하고, 스트리밍·구간 요청과 실제 재생을 구분해 검증한다.
- 회수된 파일, 저장소에 업로드된 파일, 운영에서 표시/재생된 파일은 서로 다른 단계다.
- 확보하지 못한 원본은 임의 생성하거나 다른 이미지로 대체하지 않는다. 누락 목록과 이유를 알린다.
- 공개 가능한 자료만 공개 원본 저장소에 두고, 민감 원본은 비공개 저장소에만 둔다.

## 5. 필수 동기화와 검증

프로젝트 홈과 중앙 인덱스의 `projects/projects.json`을 같은 작업 단위에서 함께 갱신한다. 실제 GitHub Pages 서비스 브랜치와 소스 브랜치가 다르면 둘의 반영 상태를 함께 확인한다.

필수 확인 항목:

1. 프로젝트의 공개/비공개 저장소, 실제 운영 URL, Git 연결이 맞는가.
2. 공개 홈에서 프로젝트 정보와 비공개 인증 링크가 보이는가.
3. 비공개 루트·본문·HTML·MD·이미지·영상·음성·ZIP 직접 주소가 인증으로 보호되는가.
4. 인증 후 요청한 자료로 돌아가며 실제 첨부가 표시·재생되는가.
5. 404/401/403/500, 잘못된 리다이렉트, 다른 저장소 연결, 실패 빌드가 없는가.
6. 운영 배포의 커밋 SHA가 실제 변경과 일치하는가.
7. 프로젝트 홈·중앙 인덱스의 등록 수·공개 범위·최신 제목·상태가 일치하는가.

`READY`는 서버 배포 상태일 뿐 미디어 완전성이나 인증 후 본문 검증 완료를 뜻하지 않는다. 검사를 실행한 CI가 성공해도 누락 결과가 0인지 별도로 읽어야 한다.

## 6. 인덱스 데이터와 표시

- `homeUrl`: 검증된 공개 홈 우선. 공개 웹이 미확인이면 해당 공개 저장소 안내를 사용할 수 있다.
- `publicUrl`, `publicRepoUrl`: 공개 서비스/안내와 공개 원본 저장소.
- `privateRepo`, `privateRepoUrl`: Private GitHub 원본 저장소와 접근 링크.
- `privateUrl`: 비공개 운영 진입 주소.
- `passwordAuthUrl`: 프로젝트 자체 비밀번호 인증 진입 주소.
- `vercelAuthUrl`: Vercel Deployment Protection 계정 인증 대상 주소. 실제 보호 활성화 여부는 별도 상태로 검증한다.
- `authModes`: `project-password`, `vercel-deployment-protection` 등 지원 인증 계층.
- `deploymentStatus`: `deployed`, `partial`, `pending`, `unverified` 등 실제 상태.
- `privateDeploymentStatus`, `privateDeploymentCommit`: 별도로 검증한 비공개 운영 배포 상태와 커밋.
- `publicHomeStatus`: 공개 안내 생성·실제 웹 검증·미존재 구분.
- `auditStatus`, `mediaStatus`, `deploymentNote`: 미완료 단계와 실제 사유.
- `pageCount`, `privatePageCount`: 등록된 채팅 페이지 수. 원본 완전성 검증과 혼동하지 않는다.
- `links`: 공개 가능한 설명과 링크. 비공개 세부 링크는 `visibility: private`, 인증 플랫폼을 명시한다.

비공개 서버에 들어가기 위한 버튼은 공개 홈 버튼과 별도로 항상 표시한다. 공개 안내가 없으면 공개된 것처럼 꾸미지 않는다.

## 7. 현재 점검 도구

`.github/workflows/archive-audit-reusable.yml`은 호출한 저장소의 추적된 실제 첨부를 검사하여 크기·SHA-256·깨진 상대 참조를 결과 아티팩트에 기록한다. 비공개 결과는 호출한 비공개 저장소에 유지한다. 과거 대화 첨부 전체를 자동 복구하거나 인증 후 재생까지 보증하는 도구가 아니다.

작업 결과에는 완료·실패·미확인을 구분하고 누락과 연결/권한 문제를 빠뜨리지 않는다.


## 절대 보존 규칙

- 기존 채팅별 상세 본문은 새 요약문으로 대체하거나 축약하지 않는다.
- 기존 `HTML`, `Markdown`, 사진, 영상, 음성, 녹취, PDF, ZIP 및 기타 첨부 원본은 누적 보존한다.
- 프로젝트 홈과 최상위 `/projects/`는 원본을 대체하는 요약 페이지가 아니라 **기존 상세 기록으로 연결하는 목차**다.
- 비공개 프로젝트는 공개 화면에서 민감 원문을 노출하지 않고, 인증 후 기존 상세본과 실제 미디어를 제공한다.
- 미디어 파일명이 목록에 있다는 이유만으로 복구 완료로 처리하지 않는다. 실제 Git 원본 존재와 웹 표시·재생까지 확인한다.
- 일반 아카이브 배포에서 상세 문서나 미디어 개수가 이전 커밋보다 감소하면 자동 보존 검사를 실패시킨다. 의도적 정리가 필요한 특수 상황만 별도 검토한다.


## 프로젝트 홈 탐색 규칙 (2026-09-30 확정)

전체 프로젝트 → 공개 GitHub Pages 프로젝트 홈 → 공개·비공개 채팅 목록 → 선택한 채팅.
프로젝트 홈은 로그인 없이 열리는 공개 목차이며 각 원본 저장소 링크를 함께 표시한다.
비공개 목록은 제목·안전한 안내·접근 주소만 공개한다. 비공개 본문과 미디어는 원래 Private 저장소에서 유지한다.
비공개 항목은 개별 원문 주소로 연결하여 서버 인증 후 해당 채팅으로 돌아간다.
동일 URL에 서로 다른 인증 이름을 붙이는 것만으로 두 인증 방식을 구현했다고 간주하지 않는다.
Vercel 계정 인증 활성화와 프로젝트 자체 비밀번호 인증은 별도로 검증한다. 선택형 인증 요청을 임의로 필수 이중 인증으로 바꾸지 않는다.
프로젝트 홈의 기본 주소는 https://softm.github.io/projects/<project>/ 이며 기존 서비스 URL과 구분한다.
